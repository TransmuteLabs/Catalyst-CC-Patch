# Проба формы

Третий потребитель общего ядра `__ccProbe` и первый детерминированный:
вердикт считается по правилам из `probes.toml`, модель не вызывается.
Механически решаемое условие модели не отдаётся (спека реестра проб, №7).

## Семь классов

| класс | событие | что читает | вердикт |
|---|---|---|---|
| A1 | бриф передан/записан | последняя непустая строка файла-брифа ≠ `<!-- BRIEF COMPLETE -->` | REFUSE |
| A2 | бриф передан/записан | арма `cargo …` без `RCH_REQUIRE_REMOTE=1 rch exec` или без `> лог 2>&1`; арма есть, а свидетель `[RCH] remote` не назван; назван `Selected worker:` | REFUSE |
| A3 | бриф передан/записан | слова открытой двери вне заборов и вне окна отрицания | REFUSE |
| A4 | бриф передан/записан | ≥ `path_lines_min` строк-путей и ни одной строки правила/перечислителя | WARN |
| B  | SendMessage, текст с головы `РЕШЕНИЕ` | нет `основани` или нет референта (`путь:строка`, `.log`/`.md`/`.diff`, sha ≥ 7 hex) | REFUSE |
| C1 | SendMessage (любой) и отчёт записан | фраза легализации вне заборов | REFUSE |
| C2 | SendMessage (любой) и отчёт записан | `Selected worker:` как свидетель без `[RCH] remote` | WARN |
| F  | Bash | `git commit` без `--only`; `git push` без `origin <ветка>:<ветка>` или с `--force`/`-f`/`--force-with-lease`; в тексте коммита трейлеры `Session:` и `Co-Authored-By:` не соседние | REFUSE |

## События и точки срабатывания

Всё — ДО исполнения инструмента, на сайте главного диспетчера, только при
`agentContext.agentType === "main"`; бросок из пробы обрабатывается тем же
путём, что бросок самого инструмента (error tool_result).

| инструмент | что оценивается |
|---|---|
| `Agent`/`Task` | каждый путь `*brief*.md`, названный в `prompt` (до 4 уникальных) — файл читается с диска |
| `SendMessage` | пути `*brief*.md` в `message` (как выше); сам `message` — классы B, C1, C2 |
| `Write` | `file_path` рода «бриф» → `content` как будущий файл (A1–A4); рода «отчёт» → C1, C2 |
| `Edit` | пост-состояние файла: текущее содержимое с заменой `old_string`→`new_string` (все вхождения при `replace_all`, иначе первое); классы по роду файла |
| `Bash` | F по тексту команды; плюс heredoc-запись в файл рода «бриф»/«отчёт» (`> путь <<'EOF' … EOF`, `>>`, `tee`, `tee -a`) — тело heredoc как будущий файл (`>>`/`tee -a` — текущий файл + тело) |

## Род файла

«Бриф» = путь по `brief_path` И голова (первая строка) по `brief_head`;
«отчёт» = путь по `report_path`. Файл рода «бриф» без совпадения головы — не
бриф: классы A к нему не применяются, путь попадает в поле `skipped` строки
журнала.

## Журнал

`~/.claude/probes/form/journal.jsonl` — одна строка на ОЦЕНКУ (знаменатель),
включая `pass`. Базовые поля ядра (`t`, `sid`, `pid`, `title`, `tool`,
`agent`, `model`, `msrc`, `cfg`, `ms`, `sw`) плюс поля пробы формы:
`outcome` (`pass|warn|refuse|…_not_enforced|skip_degraded|block_degraded`),
`tries:0`, `jm:"rules"`, `verdict`, `ev` (инструмент), `cls` (уникальные
классы), `fired` (записи `{c,n,q,src}`), `skipped`, `deg`, `rec` (имя записи).
Пример строки (свернуто):

```json
{"t":"…","sid":"…","pid":123,"tool":"Agent","ms":3,"sw":null,"outcome":"refuse",
 "cls":["A1"],"fired":[{"c":"A1","n":3,"q":"тело","src":"Agent:/path/1-brief.md"}],
 "tries":0,"jm":"rules","verdict":"REFUSE: A1×1 — Agent:/path/1-brief.md — A1 :3: тело"}
```

Каталог создаёт ядро (mkdir перед appendFile). Records — только по
срабатываниям (`record:false` при PASS): снимок `{ev, tool, sources, refuse,
warn, text}` (текст первого оценённого тела, клип 40000).

## Таблица наблюдателя и курсор

`payload` наблюдателя несёт блок `form` (из процессного состояния
`globalThis.__ccForm`, не из файла): `{enabled, seen, evals_since, since,
by_class, last, broken}` — срабатывания С прошлого тика. Курсор окна
сдвигается ТОЛЬКО после разобранного вердикта советника (хук ядра
`onVerdict`): ноль срабатываний при живой ленте — это молчание пробы, а не
чистота.

## Режимы act и инкубация

`[probe.form.act]`: `log_only` (только журнал — дефолт всех классов),
`warn` (уведомление `[form] …` в очередь task-notification, как у
наблюдателя), `cancel` (бросок с `__ccJudgeBlock`, как у судьи; класс с
вердиктом WARN при `cancel` ведёт себя как `warn` — предупреждение никогда
не отменяет). Тексты правил — `[probe.form.text]`. Включение `cancel` —
правкой конфига, без пересборки образа. `arm:!0` в коде,
`fail_closed = false` в конфиге: сбой правил не отменяет вызов.

## Включатель

`CLAUDE_FORM` не задан или пуст → проба ВКЛЮЧЕНА; `0|false|off|no` →
выключена; любое другое значение — включена (значение попадает в `sw`).
Отличие от `CLAUDE_JUDGE`/`CLAUDE_IDLE` (там пусто = выключено) намеренное:
инкубации нужен трафик, а стоковые файлы пользователя под наши данные не
правятся. Сломанные настройки гасят пробу на 10 минут (memo) с одним
уведомлением.

## Слой проекта

`<проект>/.claude/probes/probes.toml`, таблица `[probe.form]`, ложится поверх
глобальной (ключи сливаются); явный `CLAUDE_PROBES_DIR` слой отключает.

## Стенд и реплей

Стенд (`tools/probe-bench.js`) вырезает блок пробы формы из собранного образа
и гоняет сценарии через него; правила читает из `probes/probes.toml` кита —
одни данные в образе и на стенде. Реплей:

```
bun tools/probe-bench.js --binary <образ> --form-replay <путь>…
```

обходит `.md` рекурсивно, род по `__ccFormKind` (бриф/отчёт; остальные
пропускаются с подсчётом), оценивает `__ccFormEval` по правилам кита; на
каждое срабатывание печатает `FORM <файл>:<n> <класс> <refuse|warn> :: <цитата>`,
в конце — `FORM REPLAY files=<всего> briefs=<B> reports=<R> other=<O>
fired=<F> refuse=<X> warn=<Y>`. Код выхода 0 при `briefs+reports ≥ 1`, иначе 5.

## Что проба НЕ делает

Не читает транскрипт, не вызывает модель, не правит вход инструмента.
