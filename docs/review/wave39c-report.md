## Блокер 1 — ограничение области по якорю

Причина, названная контроллером, подтверждена собственным замером на
`pass3.log`: якорь `Patches applied (run with --show-unchanged to show all
patches):` встречается РОВНО ОДИН раз (строка 208), все 16 буллетов плана — до
него (первый на 132), все строки со знаками — после (первая на 211). Заголовки
секций у плана и у результатов ОДНИ И ТЕ ЖЕ (`Always Applied`,
`Misc Configurable`, `Features` встречаются по обе стороны), поэтому
перечисление исключений было обречено.

Сделано в `tools/tw-layer.sh` — единственном доме разбора:

- `TW_RESULTS_ANCHOR` — константа якоря рядом с остальными.
- `tw_results_anchor_count <файл>` — измерение числа якорей; сравнение
  ПРЕФИКСОМ (`index($0, anchor) == 1`), не регекспом: в якоре скобки и дефисы.
- Оба читателя (`tw_layer_names`, `tw_unsectioned_lines`) ограничены областью
  от якоря до конца входа; `cur` сбрасывается НА якоре, иначе заголовок секции
  из блока плана дожил бы до первой строки результатов.
- Часовой знаков получил ПРОСТОЕ правило без оговорок: строка формы правки,
  не отвечающая паре «известная секция + известный знак», — нарушитель.
  Буллеты плана вышли из предмета ПО ПОСТРОЕНИЮ.

Дверь единственности якоря — в `claude-patch-all.sh`, ПЕРВОЙ в зоне отказов
(она задаёт область всем счётам ниже), двусторонняя: ноль якорей и два якоря
разбираются отдельными текстами. Гашение слепой ручкой объявляется своим NOTE.

Свип получает то же ограничение автоматически: он подключает тот же файл.
Заглушка стенда корпусных инструментов печатает якорь, а строка берётся
ИНЪЕКЦИЕЙ из `tools/tw-layer.sh` — второй копии якоря в ките нет.

**Мутации, пинящие дверь:**

| Мутация | Что снимает | Краснит |
|---|---|---|
| `N52-scope-unbounded` | ограничение области у часового (`!inres { next }`) | N52 — буллеты плана снова становятся нарушителями |
| `N53-anchor-door-off` | дверь якоря целиком | N53 (ноль якорей) |
| `N54-anchor-made-one-sided` | `!= 1` → `< 1` | N54 (два якоря) |
| `N55-anchor-extinguish-silent` | NOTE о гашении | N55 |
| `N25-sentinel-blind` | правило часового | N25 |

## Довеска контроллера — у носителя два потребителя

### Довесок 1 — своя дверь якоря у свипа

`tools/sweep.sh` читает ВЕСЬ лог сборки, конвейер — только СВОЙ захват вывода
tweakcc. Дверь единственности якоря досталась одному конвейеру: сегодня он
зовёт tweakcc один раз за сборку, поэтому в логе якорь один, но это свойство
сегодняшнего конвейера, а не гарантия читателя. Второй вызов оставил бы дверь
конвейера зелёной (в каждом захвате по якорю) и сложил бы свипу две сборки в
один счёт при зелёном вердикте.

- `twanchor=$(num "$(tw_results_anchor_count "$log")")` — измеряется тем же
  носителем разбора (`tools/tw-layer.sh`), что и расклад слоёв, до `twcode` и
  `twprompt` (`tools/sweep.sh:1194`).
- Отказ ДВУСТОРОННИЙ и с ДВУМЯ текстами (`tools/sweep.sh:1325-1331`), каждый
  называет НАЙДЕННОЕ ЧИСЛО:
  - ноль: `якоря блока результатов tweakcc нет в логе (найдено 0) -- расклад
    слоёв посчитан по пустой области`;
  - больше одного: `якорей блока результатов tweakcc в логе 2 -- в один счёт
    сложилось несколько прогонов tweakcc`.
- Ноль и два — разные поломки: при нуле область чтения пуста и весь расклад
  врёт нулями (при исправном разборе!), при двух расклад считается верно и
  сходится, красным остаётся только сама дверь. Одним текстом их не различить.

Поля в сводке (`sum_line`) для якоря НЕ заведено намеренно: сводка несёт
ИЗМЕРЕННЫЙ расклад, а якорь — дверь, а не величина; поле потребовало бы
перепиновки дословной строки сценария 116, ничего не добавив к отказу, который
и так называет число.

### Довесок 2 — сумма крестиков производна от расклада

Было (`tools/sweep.sh:1186` прежней редакции):
`tw=$(num "$(grep -a -c '^    ✓ ' "$log")")` — третий читатель вывода форка,
мимо носителя разбора и мимо области блока результатов; предапплайный список
плана он посчитал бы наравне с результатами.

Стало (`tools/sweep.sh:1205`): `tw=$(( twcode + twprompt ))`. Расхождение суммы
с раскладом стало невозможным ПО ПОСТРОЕНИЮ. Комментарий приведён в
соответствие: галочки вне известной секции не бывает — часовой формы в
конвейере на такой строке отказывает раньше, чем сводка что-либо считает.

### Мутации, пинящие довеска (в корпусном стенде — свип его предмет)

| № | Что отменяет | Сценарий | След причины |

| 145 | дверь якоря целиком (`if false`) | 128 | `БЕЗ_ДВЕРИ_ЯКОРЯ` |
| 146 | число в тексте нулевой ветки | 128 | `ЧИСЛО_НЕ_НАЗВАНО` |
| 147 | дверь становится ОДНОСТОРОННЕЙ (только ноль) | 129 | `ДВА_ЯКОРЯ_ПРИНЯТЫ` |
| 148 | оба текста сливаются в один (`if true`) | 129 | `ТЕКСТЫ_НЕ_РАЗЛИЧЕНЫ` |
| 149 | возврат сырого `grep -a -c '^    ✓ '` | 130 | `tweakcc=5` |

Новые сценарии: **128** (`STUB_TWEAK=noanchor` — ноль якорей), **129**

сырой счёт дал бы 5 при раскладе 3+1, производная сумма даёт 4).

Ручки заглушки: якорь печатается через `case` (`noanchor` — не печатать,
`twoanchors` — дважды), плюс `planticks` — заголовок секции кода и `✓ plan only`
ДО якоря.

### Починка по ходу: режим `nopatches` обязан печатать якорь

Первая редакция гасила якорь и в `nopatches`. Самопроверка это поймала
(`покраснели=148` из 149): мутация 72, отменяющая дверь «ни одного патча»,
перестала краснить сценарий 72 своей причиной — красным его держала соседняя
дверь якоря. Предмет `nopatches` — ПУСТОЙ блок результатов, а не пропавший
блок; якорь там печатается. После починки — `покраснели=149`.

### Обзор остальных полей вердикта (просьба контроллера)

Своим образцом строки правок форка (`^    <знак> <имя>`) не разбирает больше
НИ ОДНО поле — проверено чтением всех присваиваний вердикта
(`tools/sweep.sh:1176-1270`):

- `ok`/`fail` — `[OK]`/`[FAIL]`;
- `twmiss` — `^Could not find system prompt` (якорь с начала строки);
- `ours`, `twok`, `twpart`, `twnote`, `iface`, `smoke`, `digest`, `bench`,
  `forms`, `floor`, `twlevel`, `twoff` — все читают СООБЩЕНИЯ, якоренные с
  начала строки, а не строки правок;
- `twruns = twok + twpart` и теперь `tw = twcode + twprompt` — производные.

Смежное наблюдение (флаг, не правка): `twmiss` считает по ВСЕМУ логу, а не по
области блока результатов. Сегодня это безопасно — в форке ровно один сайт
печати этого сообщения (`Catalyst-tweakcc/src/patches/systemPrompts.ts:422`), и
он лежит в проходе ПРИМЕНЕНИЯ, а не в списке плана. Если форк когда-нибудь
станет печатать промахи и в плане, поле удвоится тем же классом дефекта, что
закрыт этой волной; область для него не сужена, потому что предмет этого поля —
сообщение самого tweakcc, печатаемое с начала строки, а не строка блока.

## Довесок 3 — у двери инертных не было свидетеля

Замер контроллера по логу прогона 261: дверь инертных не сказала ни слова.
По коду она подавала голос только в трёх местах, и ни одно не было успехом
двусторонней сходимости — снятие обеих сверок не меняло ни лога, ни строки
вердикта ни на байт. Это тот же класс, что закрыт у соседей: дверь, сходящаяся
молча, неотличима от двери, которой нет.

### Пересчёт ветвей по коду (не по письму)
