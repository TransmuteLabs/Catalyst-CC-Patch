# Волна 41 — гейт интерфейса: форма `script` и проглоченный диагноз (#92)

Класс диспатча: 1c (правка прод-стадии конвейера, меняет наблюдаемое поведение
отказов; стадия выносится в функцию, чтобы у неё появился зуб). Модель: opus.
Коммитов исполнитель НЕ делает. Все прогоны — на linux (usbox).

> Номера строк сняты на дереве волны 40b (не закоммичено). Ищи по ЯКОРНОМУ
> ТЕКСТУ, а не по номеру.

## 1. Предмет: два дефекта, оба измерены

**D1. Гейт интерфейса зовёт `script` в BSD-синтаксисе.** Якорь:

```
    perl -e 'use POSIX (); POSIX::setsid(); exec @ARGV or die $!' \
    script -q /dev/null "$BIN" --strict-mcp-config "$GATE_PROMPT" >"$GATE_LOG" 2>&1
```

Захват из уцелевшего `$GATE_HOME` прогона 2.1.263 на usbox
(`/tmp/tmp.tgKehVe5L6/capture.log`, 92 байта) целиком:

```
script: unrecognized option '--strict-mcp-config'
Try 'script --help' for more information.
```

**D2. `wait` под `set -e` убивает прогон до диагноза.** Два места:

```
    GATE_EXITED=1
    wait $GATE_PID 2>/dev/null
    GATE_RC=$?
```

(внешний цикл опроса и внутренний цикл добора после первой отрисовки).
Файл идёт под `set -euo pipefail`; простая команда с ненулевым кодом обрывает
оболочку ДО присвоения. Красный зонд на linux (bash 5.2.26):

```
A: ребёнок мёртв          <- напечаталось
зонд вернул: 7            <- оболочка вышла кодом РЕБЁНКА
B: rc=…  C: дошли до конца  <- НЕ напечатались
```

Следствие: три ветки FATAL гейта (`exited N without drawing`, `never reached a
render`, `the interface does not come up`) НЕДОСТИЖИМЫ при любой ненулевой
смерти ребёнка. Прогон отдаёт голый код ребёнка и молчит — ровно поэтому
причина #80 сутки числилась неизвестной. В 240 строках выше, у дымового теста,
правильный охват `set +e` / `set -e` СТОИТ — то есть это упущение, не замысел.

**Третий сайт того же класса:** `tools/checks-on-image.sh`, якорь

```
  python3 "$BLOCK" "$IMG" "$PATCH_SRC"
  __rc_block=$?
```

При ненулевом питоне `__DONE=1` не ставится, и страж выхода докладывает
«сломалась машинерия» вместо честного отказа блока.

**Знаменатель.** Ценз проведён по ВСЕМ шести файлам кита с `set -e`
(`claude-patch-all.sh`, `tools/backup-divergence-probe.sh`,
`tools/checks-on-image.sh`, `scripts/kit-build.sh`, `scripts/probes-sync.sh`,
`patch-claude-routing.sh`): 36 кандидатов грубого прибора, настоящих ТРИ —
названные выше. Остальные — защищённая форма (`$?` в ветке `else` у
`if cmd; then`, либо `$?` первой строкой EXIT-трапа), они верны и НЕ трогаются.

## 2. Различитель формы `script` (снят на обеих машинах, обе стороны)

| команда | util-linux 2.40.2 (usbox) | BSD (macOS, bash 3.2) |
|---|---|---|
| `script -q -c true /dev/null` | rc=**0** | rc=**1** (`illegal option -- c`) |
| `script -q /dev/null /usr/bin/true` | rc=**1** (`unexpected number of arguments`) | rc=**0** |

Различитель симметричен: ровно одна из двух форм проходит. Это его собственный
положительный контроль — см. Р1.

## 3. Развилки, закрытые контроллером (открытых вопросов НЕТ)

**Р1. Форма выбирается ЗАМЕРОМ ИНСТРУМЕНТА, а не ОС хозяина.** Урок `stat -f`
(#89) — третий случай класса. Пробуются ОБЕ формы на безобидной команде
(`true`, вывод в `/dev/null`); дальше:

* ровно одна прошла → её и берём;
* прошли обе либо ни одна → **отказ кода 2** («прибор не может мерить: `script`
  на этой машине не отвечает ни одной из двух известных форм»). Молча выбрать
  одну — вернуть тот же немой отказ, из которого волна и растёт.

Проба выполняется ОДИН раз, до создания `$GATE_HOME`, рядом с проверкой
`GATE_BUDGET` (там уже стоит инвариант «между проверкой и созданием
`$GATE_HOME` не появляется ничего, что создаёт файлы или процессы» — пробу
ставить ДО него, она файлов не создаёт).

**Р2. Команда передаётся ЧЕРЕЗ СГЕНЕРИРОВАННЫЙ ЗАПУСКАТЕЛЬ, а не строкой.**
`-c` у util-linux принимает СТРОКУ, которую разбирает `sh`; ручная расстановка
кавычек стала бы вторым источником истины о команде. Поэтому:

```
{ printf '#!/usr/bin/env bash\n'
  printf 'exec %q %q %q\n' "$BIN" --strict-mcp-config "$GATE_PROMPT"
} > "$GATE_HOME/run.sh"
chmod +x "$GATE_HOME/run.sh"
```

`printf %q` — встроенная в bash, есть и в 3.2 (замерено). Запускатель исполняет
bash по шебангу, поэтому кавычки `%q` верны по построению. Вызовы:

* util-linux: `script -q -c "$(printf '%q' "$GATE_HOME/run.sh")" /dev/null`
* BSD: `script -q /dev/null "$GATE_HOME/run.sh"`

Путь запускателя тоже проходит через `%q`: `mktemp -d` может дать каталог с
пробелом, а у `-c` строку разбирает `sh`. Побочная польза: запускатель остаётся
рядом с захватом и читается человеком при разборе отказа.

**Р3. `wait` защищается, а не переставляется.** Форма во всех трёх местах одна:

```
GATE_RC=0
wait $GATE_PID 2>/dev/null || GATE_RC=$?
```

`set +e`/`set -e` вокруг НЕ использовать: охват шире одной команды, и следующая
волна вставит внутрь него что-нибудь ещё. Третий сайт
(`tools/checks-on-image.sh`) чинится той же формой.

**Р4. У стадии появляется зуб — значит, у неё появляется имя.** Блок
«запуск → опрос → вердикт» выносится в функцию `__interface_gate` в
`claude-patch-all.sh` (читает `$BIN`, `$GATE_HOME`, `$GATE_LOG`,
`$GATE_PROMPT`, `$GATE_BUDGET`; печатает свои строки; возвращает 0 либо
ненулевой код). Место вызова остаётся там же. Ничего, кроме выноса и двух
правок выше, в теле не меняется — вынос обязан быть побайтово прослеживаемым.

**Р5. Дом зуба — `tools/corpus-tools-bench.sh`.** Он на bash, умеет
`source`-ить извлечённую функцию, у него есть самопроверка мутациями и
положительные контроли. Образец извлечения функции из скрипта уже есть в
ките — `tools/costs-bench.py`, якорь `shell_function(source, "sign_macos_binary")`.

**Р6. Чего волна НЕ делает.** Не трогает платформенную ось (#80/40c — отдельная
волна), не меняет `GATE_BUDGET` и его объявление, не трогает защищённые сайты
`$?`, не переписывает разбор захвата (`gate_state`).

## 5. Зубы (без них волна не принимается)

Сценарии в `tools/corpus-tools-bench.sh`, каждый с названной причиной
покраснения и мутацией в `corpus-tools-bench.real.sh`:

* **Т1. Различитель формы.** Подставной `script` в `PATH`, принимающий ТОЛЬКО
  util-linux-форму → выбрана она; подставной, принимающий ТОЛЬКО BSD-форму →
  выбрана она. **Положительный контроль:** подставной, принимающий ОБЕ, и
  подставной, не принимающий НИ ОДНОЙ, → оба дают код 2 с названной причиной.
  Без этих двух случаев проба «выбрала форму» ничего не доказывает.
* **Т2. Достижимость КАЖДОЙ ветки вердикта.** Поддельный `$BIN` — bash-скрипт,
  ведущий себя четырьмя способами: (a) мгновенно выходит кодом 1 без вывода;
  (b) печатает приглашение и выходит кодом 1 через секунду; (c) не печатает
  ничего и живёт дольше бюджета (`GATE_BUDGET=3`); (d) печатает приглашение и
  живёт. Каждый обязан дать СВОЮ строку: (a) `exited 1 without drawing`,
  (b) `drew its message and then exited 1`, (c) `never reached a render`,
  (d) успех и снятие `$GATE_HOME`. Сегодня (a), (b) и (c) недостижимы — (c)
  проходит мимо `wait`, (a) и (b) гибнут на `set -e`.
* **Т3. Регрессия D2 напрямую.** Мутация «вернуть `wait $GATE_PID 2>/dev/null`
  без `|| GATE_RC=$?`» обязана покраснить Т2(a). Это и есть зуб, которого
  сегодня нет.
* **Т4. Регрессия D1 напрямую.** Мутация «вернуть безусловную BSD-форму»
  обязана покраснить Т1 на util-linux-подставном.
* **Т5. `checks-on-image.sh`:** при ненулевом питоне блок отвечает СВОИМ кодом,
  а не «сломалась машинерия»; мутация «снять `|| __rc_block=$?`» краснит его.

Самопроверка `--self-check` обязана остаться: измерено == покраснело,
неизмеренных ноль.
