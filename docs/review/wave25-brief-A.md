## H-1 (высшая). Удаление образа, который исполняет живая сессия

**Место:** `claude-patch-all.sh`, блок вычисления `IN_USE` (сейчас строки 5346-5366,
якорь — строка `IN_USE="$(for p in $(pgrep -x claude 2>/dev/null); do`).

**Две двери, ведущие к `rm` живого образа:**

1. `lsof` промолчал (упал, отказ в правах, вывод пуст) → `IN_USE` пуст → «никто не
   исполняет» → `rm`. Это ровно то «ответить нельзя», которое ветка отсутствующих
   инструментов выше объявляет причиной ОТКАЗА, — но достигнутое другой дверью.
2. Пробел в пути установки. `awk '$4=="txt"{print $NF}'` берёт ПОСЛЕДНЕЕ поле, а
   NAME у `lsof` — поля с 9-го до конца. Замерено на этой машине: строка
   `claude 123 mk txt REG 1,2 456 789 /Users/John Doe/.local/share/claude/versions/2.1.226`
   даёт `Doe/.local/share/claude/versions/2.1.226`. `grep -qxF` не совпадает, `rm` идёт.

**РЕШЕНИЕ (обе двери, целиком):**

* Разбор без колонок. Замерено на этой машине (Darwin, lsof):
  `lsof -a -p <pid> -d txt -Fn` печатает записи `p<pid>`, `ftxt`, `n<путь>`; имя
  достаётся `sed -n 's/^n//p'` и пробелов не боится.
  **`-a` обязателен**: без него `-p` и `-d` объединяются по ИЛИ, и в вывод попадают
  txt-файлы ЧУЖИХ процессов (замерено: без `-a` первым пришёл `loginwindow`, pid 616).
* «Спросили и не получили ответа» ≠ «никто не исполняет». Для КАЖДОГО pid из
  `pgrep -x claude`: если `lsof` не дал НИ ОДНОГО имени — это неответ. Хотя бы один
  неответ ⇒ ОТКАЗ удалять что-либо в этом прогоне, с сообщением в том же тоне, что
  и ветка отсутствующих инструментов («ответить нельзя — не удаляю на догадку»).
  Пустой список pid (claude не запущен) неответом НЕ является.
* Вынести вычисление в функцию `versions_in_use()`, печатающую по имени в строке и
  возвращающую 0 = ответ получен, 2 = ответить нельзя (код 2 единой таблицы кита:
  «прибор не может мерить»). Вызывающий ветвится по КОДУ, а не по пустоте вывода.

**Зубы (обязательны):** новый случай в `tools/build-path-probe.sh`, который кладёт в
начало `PATH` каталог со стабами `pgrep` и `lsof` и прогоняет `versions_in_use`:

* `L1` стаб lsof печатает штатный `-Fn`-вывод с ПРОБЕЛОМ в пути → путь обязан
  попасть в список ЦЕЛИКОМ;
* `L2` стаб lsof печатает пустоту при непустом `pgrep` → код 2, ни одного имени;
* `L3` стаб pgrep печатает пустоту → код 0 и пустой список (законное «никто не
  запущен»);
* `L4` стаб lsof проверяет свои аргументы: если `-a` не передан — печатает строку
  ЧУЖОГО процесса. Чужой путь в списке появиться не должен.

Каждый случай обязан КРАСНЕТЬ, если убрать соответствующую часть фикса; в отчёте
назови для каждого мутацию, которой ты это проверил.

## H-2 (высокая). Пустой каталог models.dev стирает таблицу цен

**Место:** `set-model-costs.py:624-625` (`config["customModelCosts"] = costs`) и
`candidates()` выше.

**Что происходит:** HTTP 200 с телом `{}` (или любой формы без `models`) даёт
`costs == {}`. Ветка кэша не срабатывает — она ловит только транспорт и разбор.
Дальше идёт оптовая замена, и живая таблица цен стирается. Это ровно тот откат на
запасную цену, ради предотвращения которого инструмент и существует.

**РЕШЕНИЕ:** положительный гейт перед записью. Замена НЕПУСТОЙ таблицы на ПУСТУЮ —
отказ по существу (код 1): конфиг не трогается, бэкап не снимается, причина названа
словами — сколько моделей в ростере, сколько цен нашлось, откуда каталог (сеть или
кэш). Пустая замена пустой (законно пустой ростер) отказом НЕ является. Гейт держать
на ОБЕИХ владеемых ключах — `customModelCosts` и `customModelContextWindows` — по
отдельности, у каждого своя прежняя непустота.

## H-3 (высокая). Отрицательное окно контекста пишется в конфиг

**Место:** `set-model-costs.py:189-191` (`return routed - reply_headroom()`),
потребитель — запись `windows[model_id]`.

**Что происходит:** `reply_headroom()` = `max(0, CLAUDE_CODE_MAX_OUTPUT_TOKENS - 20000)`;
документированная настройка 96000 даёт запас 76000. Модель с окном 32000 даёт
`-44000`, а единственный страж `if window:` отвергает только `0`/`None` и пропускает
ЛЮБОЕ отрицательное.

**РЕШЕНИЕ:** вычитание не имеет права выдавать неположительное. Если
`routed - reply_headroom() <= 0` — источник не годится, и порядок источников
продолжается со следующего (`limit.input`, затем `CONTEXT_OVERRIDES`/`limit.context`);
не годится ни один — окно не пишется вовсе (`None`), и модель попадает в уже
существующий перечень «no window either». Молча подставлять сырое окно БЕЗ вычета
запаса нельзя: запас существует потому, что ответ не помещается сверх окна.
Плюс страж у записи: неположительное не пишется никогда и печатает строку с именем
модели и обоими числами (окно и запас).

## H-6 (средняя). Кэш каталога без срока годности и с доверием к будущему

**Место:** `set-model-costs.py:298-303`.

**РЕШЕНИЕ:** кэш годен, если его возраст в пределах `[-60 секунд, 168 часов]`.
Отрицательный возраст (метка в будущем — переставленные часы, копия с машины
вперёд) и возраст старше недели делают кэш негодным: печатается причина и
поднимается ИСХОДНАЯ сетевая ошибка, ровно как в ветке «кэша нет вовсе».
Обе границы — именованные константы рядом с `CACHE_PATH`.

## H-9 (низкая). `_verify_tarball` принимает любой алгоритм из hashlib

**Место:** `claude_patch.py:169-179` (`alg, _, b64 = integrity.partition("-")`,
`hashlib.new(alg, blob)`).

**РЕШЕНИЕ:** допустимые алгоритмы — `{"sha512", "sha256"}`, константой рядом с
функцией. Всё прочее (включая `md5`, `sha1`) — отказ с названием алгоритма.

**Не трогать соседнюю ветку:** ниже в той же функции есть legacy-арм по
`dist.shasum` (sha1), и он объявлен в докстроке осознанно — npm публикует его для
старых пакетов. Ограничение касается ТОЛЬКО алгоритма из `dist.integrity`. Если
считаешь sha1-арм дефектом — строкой в отчёт, не правкой.

## H-8 (низкая). `prune_config_backups` сортирует чужой `ls -t`

**Место:** `claude-patch-all.sh:414`.

**РЕШЕНИЕ:** порядок брать из ИМЕНИ, а не из mtime и не из `ls`. Писатель
(`set-model-costs.py`) создаёт имена `~/.claude.json.backup.%Y%m%d-%H%M%S`, и этот
формат сортируется лексикографически как хронологический. Итерировать глоб, отбирать
только имена строгой формы (`.backup.` + 8 цифр + `-` + 6 цифр), сортировать по
имени, оставлять три последних, остальные удалять. Файлы, не подходящие под форму,
не удалять и не считать — они не наши. Метка в будущем больше ни на что не влияет.

## H-10 (низкая). `seq 1 0` на Darwin считает ВНИЗ

**Место:** `claude-patch-all.sh:5069` (`for _ in $(seq 1 "$GATE_BUDGET")`),
переменная объявлена на 5044.

**Замерено на этой машине:** `seq 1 0` печатает `1` и `0` — цикл при бюджете 0
исполняется ДВАЖДЫ, тогда как README обещает «секунды ожидания».

**РЕШЕНИЕ:** (а) счётчик `while (( i < GATE_BUDGET ))`, без `seq`; (б) проверка формы:
`CLAUDE_PATCH_GATE_BUDGET` обязан быть целым неотрицательным, иначе отказ кодом 2 с
названием полученного значения — ровно как это уже сделано для `SWEEP_LAST_N`.
Если в ЭТОМ файле читаются ещё и `SWEEP_LOCK_BUDGET`/`SWEEP_KIT_DRAIN` — им та же
проверка; если не читаются — строкой в отчёт, их дом бриф B.
