# Волна 39d — третий раунд свежих глаз по слою tweakcc

Предмет: кит `5174441`, форк `a377c40`. Две независимые дорожки третьего раунда
(A: вторая машина · полнота слепой ручки · зубы зубов; B: половина форка ·
контракт кита с форком · порядок дверей) дали 23 находки; после сведения
дубликатов и адъюдикации — 21 предмет. Раунд НЕ сошёлся.

Что подтвердил лично адъюдикатор у источника до написания брифа: F1 (порядок
проверок в цикле применения форка и условия обеих `≡`-правок), F2 (окно свипа

требует байт вне ASCII), F5 (README:377), F9 (`sum_line` без `twanchor`),
F17 (три сырых читателя).

Правило волны: найденный дефект чинится ПОЛНОСТЬЮ. Ни один предмет ниже не
закрывается комментарием «принять ограничение», тестом на текущее поведение

## F1 (высшая). Знак `≡` принадлежит конфигу машины, а объявлен как свойство пары «версия + реестр форка»

**Источник.** `Catalyst-tweakcc/src/patches/index.ts`: `:574` `versionCondition
=== false` → `skipKind:'version'` (⊘) стоит ПЕРЕД конфигом; `:588` `condition
=== false` → `skipKind:'config'` (○); и только затем исполнение → `:638`
`skipKind:'noop'` (≡). Значит `⊘` машинонезависим, а **`≡` достижим только
когда конфиг оператора оставил правку включённой**. Обе объявленные
`≡`-строки висят на тумблерах TUI: `index.ts:983`
`condition: !!config.settings.misc?.enableWorktreeMode`, `:1004`
`condition: !!config.settings.misc?.mcpConnectionNonBlocking`.

**Вход.** Оператор выключает `Worktree mode` в интерфейсе форка (штатное
действие). Форк печатает `○ Worktree mode` вместо `≡ Worktree mode`.

**Исход сегодня.** `claude-patch-all.sh:1607` → `__extra` непусто →
`:1275-1279` `FATAL: … объявлены правки tweakcc «отработало вхолостую»,
которых больше нет … Запись пережила свою причину: правка снова работает (или
ушла из реестра форка). Снимите строки из tools/tweakcc-expected-inert.txt`.
Ложный отказ сборки; диагноз называет чужого владельца; предложенное лечение
ломает машину, где тумблер включён. Это тот же класс дефекта атрибуции,
ради снятия которого волна 39c и раскалывала кружок.

**Закреплённый дизайн (решение адъюдикатора).** Дверь становится
ДВУХРЕЖИМНОЙ по знаку — `__tw_inert_check_sign`, `claude-patch-all.sh:1258-1283`:

- знак `⊘` — обе стороны отказывают, как сейчас (`__miss` и `__extra`);
- знак `≡` — сторона `__miss` (измерено, не объявлено) отказывает, как сейчас;
  сторона `__extra` (объявлено, не измерено) отказывает ТОЛЬКО если имя
  измерено как `✓` или `✗`, либо его нет в выводе форка вовсе. Если имя
  измерено как `○` — дверь МОЛЧИТ: оператор выключил тумблер, и этот исход уже
  гейтится двусторонне дверью множества выключенных, чей дом — машина
  (`~/.tweakcc/catalyst-expected-off.txt`).

Сообщения отказа расщепить так, чтобы каждая ветка называла СВОЮ причину:
«правка вернулась к жизни» (измерено `✓`/`✗`) и «правка ушла из реестра форка»
(имени нет в выводе). Общая формулировка «(или ушла из реестра форка)»
снимается — она и есть смешение причин.

**Шапка объявления** `tools/tweakcc-expected-inert.txt:9-15` переписывается:
владелец `⊘` — пара «версия апстрима + реестр форка»; владелец `≡` — ТРОЙКА
«версия + реестр форка + конфиг дома», и потому его сторона «объявлено, но не
измерено» ослаблена ровно на исход `○`, с указанием, какая дверь его держит.

**Зубы (обязательны, иначе предмет не закрыт).** Три новые мутации случая (n)
`tools/build-path-probe.sh`:
1. объявленный `≡` измерен как `○` → дверь молчит; мутация, возвращающая
   безусловный отказ, ОБЯЗАНА краснеть (пин самой послабки);
2. объявленный `≡` измерен как `✓` → отказ своей причиной («вернулась к жизни»);
3. объявленное `≡`-имя отсутствует в выводе → отказ своей причиной («ушла из
   реестра форка»).

# Принято без правки (адъюдикация)

- **Мёртвые термы `__pfail`** (`:1637 && __pfail == 0`, `:1718 || __pfail > 0`).
  Не могут сработать, пока стоит дверь `:1439`. Принимаю объяснение дорожки A:
  это оборона от снятия двери, а не мёртвый код; комментарий `:1633-1636` это
  раскрывает. Правки не требуют — но формулировка тела коммита 39c
  («ветка схождения требует и нулевого числа крестиков») читается как
  действующее требование; при следующем описании не повторять.
- **`✓` не проверяется на «изменил не там»** (`applied = result !== content`).
  Свойство исходного механизма форка, волна 39c его не трогала. Заводится
  отдельной задачей, в эту волну не входит.
- **`skipKind:'filter'` печатается кружком** — сворачивается в волну 39e (F3).

# ВОЛНА 39e (заводится сейчас, не откладывается): половина форка сделана в одном из двух производителей

`Catalyst-tweakcc/src/patches/index.ts:147-149` — комментарий на ОБЩЕМ типе
`PatchResult`: «Every branch that leaves `applied` false sets this, so an unset
value means "landed or failed", never "some third thing nobody labelled"».
Проверено адъюдикатором: в `src/patches/systemPrompts.ts` вхождений `skipKind`
РОВНО НОЛЬ, а ветки, оставляющие `applied` ложным, есть на `:189` (фильтр),
`:219` («regex too complex»), `:350` («stale identifier»), `:411` (вычисленный
`applied`). Печать `src/index.tsx:152-161` даёт им всем тусклый кружок.

Замер дорожки B по живому логу 2.1.261: `System Prompts|○ 607`, из них 598
«unchanged» и **9 «stale identifier»** — накладки оператора, которые НЕ легли,
потому что их идентификаторы интерполяции ушли из апстрима. Они печатаются
знаком, который волна 39c определила как «оператор выключил её сам». Заявленная
цель волны в слое промтов не достигнута, и объём там в 26 раз больше, чем в
слое кода. Тест `skipKind.test.ts` этого не ловит по построению: инвариант
проверяется только для `applyPatchImplementations`, тогда как утверждение
записано на общем типе.

**Почему отдельной волной, а не этой.** Честный знак для веток `:219` и `:350`
— `✗` («пробовалась и не легла»): это правда, и дверь `__pfail` конвейера
тогда ЗАКОННО покраснеет на девяти накладках живой машины. Каталог накладок
принадлежит оператору, и что делать с девятью устаревшими накладками — решение
не исполнителя. Слой промтов и слой кода по знакам не пересекаются (объявление
инертных читает только секции кода), поэтому каденция F2 может быть снята до
39e и от неё не устареет. Волна 39e = полный контракт типа у обоих
производителей + различающие знаки + расширение теста на второго производителя
+ разбор девяти накладок с адъюдикатором.
