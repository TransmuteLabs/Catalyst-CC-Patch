## Находка 1 — раскол крестиков пинится ЗНАЧЕНИЕМ, а не владельцем

`tools/sweep.sh` делит крестики tweakcc на два слоя:

```
  twcode=$(num "$(grep -a '^    ✓ ' "$log" | grep -a -c -v -E "^    ✓ (${__tw_types}): ")")
  twprompt=$(num "$(grep -a -c -E "^    ✓ (${__tw_types}): " "$log")")
```

Заглушка печатает РОВНО по одной строке на слой, поэтому расклад `1/1`
симметричен: поменяй два грепа ролями — расклад останется `1/1`, и пин
сценария 116 пройдёт. На живом образе (код 13, промты 20) такая перестановка
молча приписала бы просадку кода накладкам.

### Правка 1.1 — асимметричный лог заглушки

`tools/corpus-tools-bench.sh`, тело заглушки конвейера. Сейчас:

```
unless nopatches  '    ✓ site'
unless nopatches  "    ✓ ${__TW_PROMPT_TYPES%%|*}: stub"
```

Стало (три строки: ОДИН код, ДВА промта — из первых двух типов списка):

```
# Лог АСИММЕТРИЧЕН намеренно: при раскладе 1/1 перестановка двух грепов свипа
# ролями оставляет расклад неизменным, и пин сценария 116 теряет зуб.
__tw_t1="${__TW_PROMPT_TYPES%%|*}"
__tw_rest="${__TW_PROMPT_TYPES#*|}"
__tw_t2="${__tw_rest%%|*}"
unless nopatches  '    ✓ site'
unless nopatches  "    ✓ ${__tw_t1}: stub"
unless nopatches  "    ✓ ${__tw_t2}: stub"
```

Три присваивания ставятся в теле заглушки ДО первой строки `unless nopatches`,
после присваивания `tweak=`. Имена локальны для заглушки, `set -u` в ней не
включён — объявлять их иначе не требуется.

### Правка 1.2 — пин сценария 116

`scenario_116`: строка сравнения и строка `bad` переходят с
`tweakcc=2 twcode=1 twprompt=1 twmiss=2` на
`tweakcc=3 twcode=1 twprompt=2 twmiss=2` (обе — и условие, и текст ошибки).

### Правка 1.3 — мутация владельца (новая, №136)

Мутация снимает `-v` у счётчика кода: он начинает считать те же строки, что и
счётчик накладок. На СТАРОМ симметричном логе это давало `twcode=1` и было
невидимо; на новом даёт `twcode=2`.

* `MUT_FILE`  → `tools/sweep.sh`
* `MUT_PAT`   → `'grep \-a \-c \-v \-E "\^    ✓ \(\$\{__tw_types\}\): "'`
* `MUT_REP`   → `'grep -a -c -E "^    ✓ (${__tw_types}): "'`
* `MUT_SCENARIO` → `116`
* `MUT_CAUSE` → `'twcode=2'`

### Правка 1.4 — причина мутации 132 протухла

Мутация с заменой `'-c -v -E "^    ✓ (${__tw_types}):  "'` (лишний пробел)
на новом логе даёт `twcode=3`, а не `twcode=2`. Её запись в `MUT_CAUSE`
меняется `'twcode=2'` → `'twcode=3'`. Это ПОСЛЕДНЯЯ из старых записей со
значением `twcode=2`; новая запись 136 занимает это значение.

## Находка 2 — единственность якоря `__TW_PROMPT_TYPES` объявлена, но не охраняется

Присваивание читают ТРИ потребителя, и все берут ПЕРВОЕ совпадение
(`sed … | head -1`, `sed … | head -1`, `re.search`). Bash же при двух
присваиваниях на верхнем уровне берёт ПОСЛЕДНЕЕ. Второе присваивание тихо
развело бы счёт свипа с поведением конвейера. Сегодня совпадение ровно одно —
инвариант держится случайно.

### Правка 2.1 — страж в `tools/sweep.sh`

Блок чтения списка (сегодня — счёт через `sed … | head -1` и проверка `-z`)
заменяется на:

```bash
# У присваивания ОДИН владелец -- конвейер, и bash берёт ПОСЛЕДНЕЕ из
# нескольких. Читатели же берут первое, поэтому второе присваивание развело бы
# счёт свипа с поведением конвейера молча. Единственность -- предусловие, а не
# удобство: отказ до первой сборки, а не `head -1`.
__tw_types_hits=$(grep -a -c '^__TW_PROMPT_TYPES=' "$HERE/claude-patch-all.sh")
if (( __tw_types_hits != 1 )); then
  if (( __tw_types_hits == 0 )); then
    echo "SWEEP ОТКАЗ: в снимке кита не найдено присваивание __TW_PROMPT_TYPES -- расклад крестиков считать нечем" >&2
  else
    echo "SWEEP ОТКАЗ: в снимке кита присваиваний __TW_PROMPT_TYPES несколько ($__tw_types_hits) -- конвейер возьмёт последнее, а счёт пошёл бы по первому" >&2
  fi
  exit 1
fi
TW_PROMPT_TYPES=$(sed -n "s/^__TW_PROMPT_TYPES='\(.*\)'\$/\1/p" "$HERE/claude-patch-all.sh")
if [[ -z "$TW_PROMPT_TYPES" ]]; then
  echo "SWEEP ОТКАЗ: присваивание __TW_PROMPT_TYPES в снимке кита не разобрано -- расклад крестиков считать нечем" >&2
  exit 1
fi
```

Обрати внимание на три вещи, каждая обязательна:
* якорь СЧЁТА — `^__TW_PROMPT_TYPES=` (без кавычки), чтобы неразобранная форма
  (двойные кавычки) прошла счёт и дошла до проверки разбора;
* якорь РАЗБОРА остаётся с одинарной кавычкой — как сегодня;
* `head -1` у `sed` СНИМАЕТСЯ: единственность уже доказана выше, и `head -1`
  здесь был бы вторым, молчаливым ответом на тот же вопрос.

Существующий комментарий над блоком (про принадлежность списка конвейеру)
сохраняется.

### Правка 2.2 — страж в `tools/corpus-tools-bench.sh` (сборка игрушечного кита)

Там же, где сегодня `__types_line=$(sed -n … | head -1)` и отказ по пустоте,
перед вырезкой добавляется счёт с тем же направлением отказа:

```bash
__types_hits=$(grep -a -c "^__TW_PROMPT_TYPES=" "$dir/claude-patch-all.real")
if [[ "$__types_hits" != 1 ]]; then
  echo "corpus-tools-bench: в ките присваиваний __TW_PROMPT_TYPES $__types_hits, а нужно ровно одно --" >&2
  echo "  заглушка повторила бы не ту строку, которую исполняет конвейер." >&2
  exit 2
fi
```

Существующая ветка отказа по пустой строке сохраняется (она ловит случай, когда
счёт сошёлся, а `sed` не разобрал). `head -1` у `sed` СНИМАЕТСЯ.

### Правка 2.3 — страж в `tools/build-path-probe.sh`

В блоке извлечения механизма уровня tweakcc `re.search` по типам заменяется на
`re.findall`, и множественность попадает в тот же отказ:

if len(types) != 1 or not door or not all(counters):

Счётчики зонда (`EXPECTED_SCENARIOS`, `EXPECTED_MUTATIONS`) НЕ меняются: это

## Находка 3 — код возврата подстановки списка не проверяется

`tools/corpus-tools-bench.sh` под `set -u` без `set -e`: падение `python3`
(нет в PATH, файл не читается, сработал внутренний `SystemExit(2)`) оставило бы
метку `@@TW_PROMPT_TYPES@@` в заглушке. Метка НЕПУСТА, поэтому отказ свипа не
сработает — и вина легла бы на свип, ровно как в случае, против которого
написан соседний комментарий.

Вызов оборачивается проверкой:

```bash
if ! python3 - "$dir/claude-patch-all.sh" "$__types_line" <<'INJECT'
…тело без изменений…
INJECT
then
  echo "corpus-tools-bench: подстановка списка типов в заглушку не удалась --" >&2
  echo "  метка осталась бы на месте, и отказ свипа не сработал бы: вина легла бы на свип." >&2
  exit 2
fi
```

Сценария у этой правки НЕТ — по прецеденту самого файла: предусловия ПРИБОРА
(`require_no_real_run`, `wait_holder_ready`, отказ по отсутствию строки типов)
сценариями не покрываются, а движок мутаций правит копию кита, в которой сам
стенд не исполняется. Счётчики от этой правки не меняются.

## Находка 4 — режим `nomiss` заглушки не выбирается ни одним сценарием

Все четыре строки промаха накладок стоят под `unless nomiss`, но `nomiss` не
выбирает никто. Поле `twmiss` пинится единственным значением `2`, поэтому
подмена счётчика КОНСТАНТОЙ `2` проходит весь стенд.

### Правка 4.1 — сценарий 121 (новый)

```bash
scenario_121() {   # промахов накладок нет -- поле обязано быть НУЛЁМ
  # Единственное пиненное значение поля переживает подмену счётчика константой
  # этого же значения. Нулевой случай -- вторая точка, через которую константа
  # уже не проходит.
  local out rc line summary
  summary="$S/log/sweep-summary.txt"
  out=$(STUB_TWEAK=nomiss run_sweep "$K" "$C/corpus" "$C/versions.txt" 900); rc=$?
  LAST_EVID="rc=$rc :: $out"
  if (( rc != 0 )); then
    bad "121 лог без промахов накладок: зелёный прогон не состоялся (код $rc)"; return
  fi
  line=$(grep -a 'twmiss=' "$summary" 2>/dev/null | head -1)
  LAST_EVID="РАСКЛАД :: $line"
  if [[ "$line" != *"twmiss=0"* ]]; then
    bad "121 лог без промахов накладок: в сводке не «twmiss=0»; было: $line"; return
  fi
  ok "121 отсутствие промахов накладок читается нулём"
}
```

### Правка 4.2 — мутация константы (новая, №139)

* `MUT_FILE` → `tools/sweep.sh`
* `MUT_PAT`  → `'  twmiss=\$\(num '`
* `MUT_REP`  → `'  twmiss=2; : $(num '`
* `MUT_SCENARIO` → `121`
* `MUT_CAUSE` → `'twmiss=2'`

Замена оставляет остаток строки целым и синтаксически годным: значение
становится константой `2`, сценарий 116 (пин `twmiss=2`) её не замечает,
сценарий 121 (пин `twmiss=0`) краснеет.

## Находка 5 — комментарий обобщает живой замер на игрушечные данные

В шапке `scenario_116` сказано, что промахи «считались бы вдвое, если снять
якорь». Удвоение — свойство ЖИВОГО образа (2.1.259: 24 → 48). На игрушечном
логе неякоренный счёт даёт 3 при 2 якорных, потому что пересказ конвейера
несёт образец внутри себя только у НЕРАЗОБРАННОГО промаха. Записанная причина
мутации (`twmiss=3`) честна — расходится только текст.

Формулировка приводится к замеру: назвать удвоение свойством живого образа с
числами 24→48, а для игрушечного лога назвать 3 против 2 и причину (образец
внутри строки пересказа у неразобранной ветки). Числа 24, 48, 3 и 2 в этой
формулировке — прозаические, гейт чисел их не пинит; если он всё же назовёт их
объявлениями, сообщи в отчёте, НЕ глуши гейт.
