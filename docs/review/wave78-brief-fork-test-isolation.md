## Что сделать

### 1. Назвать писателя ИЗМЕРЕНИЕМ

Опыт ставить ТОЛЬКО на копии дома. Живой `~/.tweakcc` в поиске виновника не
участвует: три порчи уже случились, четвёртой быть не должно.

Обязательная форма стенда поиска (её же оставить в дереве как инструмент):
снять снимок дома, прогнать ОДИН файл теста, сверить md5, откатить снимок,
перейти к следующему. Файлы гонять по одному, а не пачкой: пачка называет
множество, а нужен файл.

Подозреваемые из прошлой разведки (список НЕ закрыт, проверять все файлы):
`src/tests/config.test.ts`, `src/tests/migration.test.ts`,
`src/tests/tweakccConfigDir.test.ts`, `src/patches/applyPlan.test.ts`.

Отдельным опытом развести две переменные: прогнать виновника с одним только
`HOME`, затем с одним только `TWEAKCC_CONFIG_DIR`. Назвать, что именно держит
дом. Без этого замера фикс пункта 2 не проверяем.

### 2. Починить корень

Ни один тест не читает и не пишет `~/.tweakcc` без явной подмены дома. Опора в
форке уже есть — переменная `TWEAKCC_CONFIG_DIR` и `src/tests/tweakccConfigDir.test.ts`;
механизм существует и виновником не используется. Чинить ИМ, а не новым.

Условие приёмки фикса: полный `npx vitest run` БЕЗ каких-либо подмен в
окружении оставляет `~/.tweakcc/config.json` побайтово неизменным, и при этом
даёт прежний счёт `Test Files 52 passed`, `Tests 596 passed | 5 skipped (601)`.
Меньший счёт означает, что тест перестал что-то проверять — это находка, а не
успех. Больший — объяснить в отчёте.

Правки в тестах поиска путей установки (`getClijsSearchPathsWithInfo`,
`getNativeSearchPathsWithInfo`) в предмет НЕ входят: они падали только под моей
подменой `HOME`, а без подмен проходят.

### 3. Зуб

Случай, краснеющий, когда тест снова пишет в живой дом. Форма: после полного
прогона содержимое и mtime `~/.tweakcc/config.json` не изменились.

Зуб обязан краснеть на ТЕКУЩЕМ коде — проверить ДО фикса и записать сырой вывод
в отчёт. Зуб, зелёный до фикса, ничего не пинит.

Дом зуба выбрать так, чтобы он гонялся сам: если это тест форка — он часть
`vitest run`; если проверка кита — назвать, каким гейтом она вызывается.

## Скоуп записи

Только `Catalyst-tweakcc/`: файлы тестов, при необходимости их опоры, стенд
поиска виновника, `docs/` форка при наличии. Кит НЕ трогать.

## Правила

- Живой `~/.tweakcc` НЕ портить. Перед любым прогоном без подмен — снимок и
  побайтовый откат при расхождении md5.
- Коммитов НЕ делать: изменения остаются в рабочем дереве, коммитит контроллер.
- Комментарий в коде несёт только констрейнт, не нарратив правки.
- Неожиданное расхождение с брифом → одна честная попытка → BLOCKED с сырым
  выводом, без глубокой диагностики.
- Отчёт: `docs/review/wave78-report.md` В ДЕРЕВЕ КИТА (кит только для отчёта,
  кода кита не трогать) — виновник поимённо, вывод разводящего опыта по двум
  переменным, счётчики тестов ДО и ПОСЛЕ, сырой вывод зуба до фикса и после.
