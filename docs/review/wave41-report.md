## 2. Две правки сверх текста брифа (обе — следствие его же работ)

**2.1. Форма ВЫЗОВА стадии: голое имя вместо `|| exit $?`.** Первая редакция
звала вынесенную функцию как `__interface_gate || exit $?`. Самопроверка стенда
поймала это немедленно: мутации 182 и 183 (снятие защиты с обеих площадок
`wait`) прошли МОЛЧА. Замер причины:

```
$ bash /tmp/w41probe4.sh; echo "зонд4 вернул: $?"
A. вызов через ||:
  внутри: дошли до присвоения, rc=7      <- set -e НЕ сработал во всём теле
B. вызов голым именем:
зонд4 вернул: 7                          <- set -e оборвал тело на wait
```

У функции, стоящей в AND-OR списке, `set -e` игнорируется ВО ВСЁМ ТЕЛЕ. То есть
форма с `||` молча сняла бы с вынесенного тела ту самую оболочку, под которой оно
жило до выноса (Р4: «ничего, кроме выноса и двух правок, в теле не меняется»), и
заодно погасила бы зубы этой волны. Стадия зовётся голым именем; ненулевой
возврат под `set -e` кончает прогон тем же кодом, каким стадия выходила до
выноса (EXIT-трап конвейера ведёт себя так же: `__rc != 0` → `exit "$__rc"`).

**2.2. Дословная форма чтения метаданных в комментарии.** Первая редакция
комментария пробы называла класс дефекта образцом формы `stat` — сценарий 146
(ценз формы по трём домам) покраснел на `claude-patch-all.real=1`. Класс назван
именем, а не образцом; в README то же место переформулировано.

## 5. Что НЕ сделано и почему

### 5.1 БЛОКЕР: `tools/lock-probe.sh` пинит снятую форму запуска (вне области записи)

Нога 8 прибора замка (`tools/lock-probe.sh:351`) ищет в конвейере ДОСЛОВНУЮ
строку запуска гейта и требует, чтобы следующая строка была `) 9>&- &`:

```
GATE_SPAWN="$(grep -n 'script -q /dev/null "\$BIN" --strict-mcp-config "\$GATE_PROMPT"' "$PIPELINE" | head -1 | cut -d: -f1)"
...
  [[ "$GATE_CLOSE" == ') 9>&- &' ]] \
```

Волна снимает эту строку ПО УСТРОЙСТВУ (в этом и состоит D1), поэтому нога
краснеет отказом «прибор смотрит не туда»:

```
lock-probe rc=1
  FAIL   в конвейере не найден запуск гейта интерфейса -- прибор смотрит не туда
lock-probe: ПРОВАЛ -- 1 утверждений не держатся
```

Отказ едет дальше по цепочке: `build-path-probe` не меряет путь сборки на
сломанном замке → `corpus-tools-bench` отказывает на сценарии 91 («нога „зонд“
не измерена») и до сценариев 150–157 не доходит. Остальные 30 утверждений
прибора замка зелены; красная — только эта.

`tools/lock-probe.sh` НЕ входит в область записи волны (бриф §6), поэтому в
дереве он НЕ правлен. Минимальная правка замерена на ЗАМЕРНОЙ КОПИИ кита
(`~/ccpatch/kit41m`, вне дерева репозитория) — две строки:

* якорь → `grep -n '"\${__gate_cmd\[@\]}" >"\$GATE_LOG" 2>&1' "$PIPELINE"`;
* ожидаемая строка → `'  ) 9>&- &'` (два пробела: стадия теперь внутри функции).

С ней `lock-probe rc=0` («все утверждения держатся»), стенд проходит целиком
(`bench rc=0`, `bench-self rc=0`). Решение о расширении области записи — за
контроллером; без него стенд корпусных инструментов на этом дереве не зелен.

### 5.2 Расхождение с брифом: симптом D3 на bash 5.2 не воспроизводится

Бриф (§1, третий сайт) утверждает, что при ненулевом питоне страж выхода
`checks-on-image.sh` «докладывает „сломалась машинерия“ вместо честного отказа
блока». Замер на usbox (bash 5.2.26) — зонд формы и настоящий инструмент:

```
$ bash /tmp/w41probe1.sh; echo "зонд1 вернул: $?"
зонд1 вернул: 7
GUARD: rc=7 DONE=0                 <- строка «прогон оборвался» НЕ печатается

$ bash tools/checks-on-image.sh /tmp/w41toy.img    # блок красен: 117 [FAIL]
checks-on-image rc=1
grep -c "оборвался" = 0
```

На этой оболочке коды ДО и ПОСЛЕ правки совпадают: обрыв по `set -e` отдаёт тот
же код, что и честный хвост. Отличается ГАРАНТИЯ: отметка `__DONE` не ставится,
и часовой оборванного прогона — написанный как раз для оболочки, которая теряет
код, — на красном блоке начинает зависеть от кода, который сам же и не
контролирует. Правка сделана ПОЛНОСТЬЮ по форме Р3. Зуб Т5 поэтому двуногий:
поведение (код блока доехал, строки обрыва нет) — положительный контроль, а
мутация «снять `|| __rc_block=$?`» краснит ногу ФОРМЫ, прочитанную из копии
кита (тот же класс, что ноги формы сценариев 85, 86 и 149). Симптом на bash 3.2
не проверялся: все прогоны волны — на linux по условию диспатча.
