## 1. `SWEEP_LAST_N` — десятичная база И запрет пустого набора (K-4)

Сейчас (`tools/sweep.sh:543-556`) `case` пропускает любую строку из цифр, а
арифметика bash восьмеричная. Под `set -u` без `set -e`: `SWEEP_LAST_N=08` →
`(( 08 == 0 ))` падает, ветка «весь корпус» не берётся, срез падает, `SRC`
пуст — и хвост (`:1143`) печатает **«SWEEP DONE: все 0 версий измерены, красных
нет», код 0**. `0010` даёт восьмеричные 8 версий, а объявление несёт `0010`.

Правка A — база. Тот же кит уже умеет правильно:
`validated_nonnegative_integer` в `claude-patch-all.sh:5238` снимает ведущие
нули, ловит переполнение и считает `$((10#$digits))`. Перенести ЭТОТ алгоритм в
`sweep.sh` дословно (общий файл-библиотеку НЕ заводить: списки копирования кита
пришлось бы править в нескольких местах, и пропуск одного убивает конвейер).
В обеих точках — комментарий-перекрёстка: «вторая копия правила живёт в
<файл:строка>; расхождение ловится сценарием стенда, а не чтением».

Правка B — корень, а не симптом. Пустой набор версий обязан быть ОТКАЗОМ, а не
зелёным хвостом. Сразу после формирования `SRC`:

    if (( ${#SRC[@]} == 0 )); then
      echo "SWEEP ОТКАЗ: набор версий пуст -- мерить нечего" >&2
      exit 5
    fi

Код 5 — по таблице кодов в шапке файла («нечего мерить»). Эта проверка стоит
независимо от того, чем набор опустел: она закрывает и будущие пути, а не только
восьмеричный.

## 2. Снос обломка — только через примитив ожидания (L-1)

Сейчас `rm -rf "$__stale"` (`:386-391`) исполняется РАНЬШЕ проверки живых
процессов (`:446-459`). Конвейер намеренно запускается без дескриптора замка
(`:983-984`, `8>&-`), поэтому осиротевший `claude-patch-all.sh` штатно не держит
ничего: следующий свип берёт свободный замок и сносит каталог из-под живого
ребёнка. Измерено аудитором: каталог удалён, процесс жив, и лишь ЗАТЕМ отказ 3.

В этом же файле уже есть правильный примитив — `__drop_kit_when_idle`
(`:149`). Получить:

* `__drop_kit_when_idle [путь] [бюджет]`: путь по умолчанию `$HERE`, бюджет по
  умолчанию `${SWEEP_KIT_DRAIN:-60}`.
* `__GUARD_KIT=0` снимается ТОЛЬКО когда путь равен `$HERE` (флаг принадлежит
  своему снимку, чужой обломок к нему отношения не имеет).
* Проверка жильцов (`ps -eo pid,args` + `index($0, path)`) стоит непосредственно
  перед `rm -rf` — между ними ничего.
* Чужие обломки идут с бюджетом **0**: одна проверка, без ожидания. Ждать за
  мёртвый прогон не наше дело; снести из-под живого — наше.
* Жильцы найдены → каталог остаётся, печатается существующая строка «снимок кита
  НЕ убран», прогон продолжается.

Цикл прополки (`:386-391`) переводится на этот примитив для `kit.??????` **и**
`sweep.self.??????` (из обоих ИСПОЛНЯЮТСЯ процессы). `sweep.pgid` — файл данных,
его никто не исполняет: остаётся прямой `rm -f`, и комментарий обязан назвать,
почему эти двое разные.

## 3. Цель патчера выбирается по ДОПУСТИМОЙ форме имени (L-2)

Сейчас (`claude_patch.py:301-307`) отбор идёт вычитанием суффиксов:

    skip = (".orig", ".staging", ".restore", ".repair", ".new", ".tmp", ".bak", ".download")
    cands = [p for p in vdir.iterdir() if p.is_file() and not p.name.endswith(skip)]
    return max(cands, key=lambda p: p.stat().st_mtime)

Отрицательный список не знает имён, которых ещё не придумали. Собственный
`tempfile.mkstemp(prefix=".claude-patched-", dir=target.parent, ...)` (`:539-540`)
под него не подпадает — и он САМЫЙ СВЕЖИЙ по mtime. Умерший до `os.replace`
процесс оставляет файл, который второй запуск выбирает целью, видит в нём наш
маркер и печатает «Already patched — nothing to do.», не тронув установленный
бинарник (измерено аудитором на изолированном каталоге).

Получить положительное правило: кандидат — файл, чьё имя ЦЕЛИКОМ совпадает с
`^\d+\.\d+\.\d+$` (на Windows — то же плюс суффикс `.exe`). Живой каталог версий
сегодня содержит ровно `2.1.250 2.1.250.orig 2.1.251 2.1.251.orig` — правило
берёт две настоящие версии и ни одного обломка.

Кандидатов нет → существующий `die(..., code=2)`, но причина названа явно:
в каталоге нет файла с ИМЕНЕМ ВЕРСИИ, а обломок оборванного прогона целью не
бывает. Тупой отказ здесь дешевле молчаливого успеха над остатком.

Кортеж `skip` удаляется; на его месте — комментарий, фиксирующий, ПОЧЕМУ
отрицательный список брошен (его нельзя дописать до полноты; предыдущая правка
дописывала в него `.download`, и следующая дописывала бы `.claude-patched-`).

## 4. Промежуточное имя принадлежит писателю (L-7)

`_replace_backup` (`claude_patch.py:469-480`) стажирует в фиксированное
`<backup>.new`. Два самостоятельных запуска делят один inode: измерено, что B
переименовал файл, пока A писал в уже открытый дескриптор, и опубликованный
backup собрался из половин обоих.

Параллельный прямой запуск — ПОДДЕРЖИВАЕМАЯ поверхность: страж живых процессов в
`sweep.sh` существует ровно потому, что «оператор вправе собирать в соседнем
окне».

Получить: `tmp = backup.with_name(backup.name + f".new.{os.getpid()}")`.

Дальше — мехнический свип по тому же правилу: в `claude_patch.py` найти
(`grep -n 'with_name\|"\.new"\|\.tmp\b'`) КАЖДОЕ фиксированное промежуточное имя,
которое могут разделить два процесса, и добавить в него `os.getpid()`. Правило
закрытое: фиксированное стажирующее имя ⇒ `.<pid>`. Все найденные имена
перечислить в отчёте.

Правки 3 и 4 обязаны лечь ВМЕСТЕ: `.new.<pid>` не ловится суффиксным
`endswith(".new")`, поэтому починка одной в одиночку открывает новый класс
остатка в другой.

## 5. Осиротевшая стадия `probes-sync` — владелец, а не номер (L-8)

`prune_one_sync_stage` и `report_one_sync_stage` (`scripts/probes-sync.sh:294-319`)
проверяют только `kill -0 <pid>`. Номер принадлежит УЖЕ УМЕРШЕМУ писателю: если
номер достался постороннему долгоживущему процессу, многолетняя стадия считается
активной записью. Измерено: stage с mtime 2020 года и PID постороннего `sleep` —
`--diff` вернул 0 со строкой «стадия живого писателя», `--to-home` оставил файл.

В ЭТОМ ЖЕ ФАЙЛЕ каталог-замок уже сверяет PID вместе со временем старта
(`:243-246`, формат `pid<TAB>lstart`, пустая метка = решение по `kill -0`).

Получить: та же дисциплина у стадии.

* Писатель ДО создания стадии пишет файл-владелец
  `<файл>.sync-owner.<pid>` со строкой `pid<TAB>$(LC_ALL=C ps -o lstart= -p $$)`.
  Имя намеренно с ДРУГИМ инфиксом: `for_each_sync_stage` глобит
  `"${PAIR_B[$i]}.sync-new."*`, и сосед с суффиксом `.owner` попал бы в этот
  глоб как ещё одна стадия.
* Живым писателем стадия считается, только если владелец существует, номер жив
  И `lstart` совпадает. Нет файла-владельца при существующей стадии ⇒ мёртвый
  (порядок записи это гарантирует).
* Прополка сносит стадию вместе с её файлом-владельцем.

## 6. Одна истинность у env-ручек кита (K-10)

Замерено аудитором: три языка в одном ките — `CLAUDE_PATCH_SKIP_MODELS` строго
`== "1"` (`claude-patch-all.sh:5731`), `SWEEP_SKIP_*` и `KEEP_ROOT` по `-n`.

цен без объявления), `SWEEP_SKIP_BUILD_PROBE=0` зонд ПРОПУСКАЕТ, `KEEP_ROOT=0`

библиотеку не заводить — причина та же, что в правке 1), с комментарием-

    # Значения-истина: 1 true yes on (без учёта регистра). Ложь: пусто,

    # в оболочке отказ дёшев и громок, а тихо выбранная сторона у ручки,

    # (В ядре, tweakcc-patch.js, та же семья решена иначе -- безопасная сторона
    # плюс строка в журнал: там отказ убил бы живую сессию человека.)
    __envon() { ... }

Перевести: `CLAUDE_PATCH_SKIP_MODELS`, `SWEEP_SKIP_BUILD_PROBE`,
`SWEEP_SKIP_TOOLS_BENCH`, `SWEEP_SKIP_CHECKS_TEETH`, `KEEP_ROOT` (в
`tools/lock-probe.sh` И в `tools/build-path-probe.sh` — проверить обоих
`grep -rn 'KEEP_ROOT' tools/`). Затем `grep -rn '\-n "\${[A-Z_]*:-}"' tools/ scripts/ claude-patch-all.sh`
и перечислить в отчёте все прочие ручки этой семьи, найденные, но НЕ переведённые

**Смена поведения, которую обязан назвать отчёт:** `SWEEP_SKIP_BUILD_PROBE=0`

## Зубы

Каждое утверждение — с названной мутацией, красящей СВОЙ сценарий СВОЕЙ
причиной. Мутант, падающий с ошибкой сборки/разбора, покраснением НЕ считается.

Дом сценариев — существующий стенд корпусных инструментов
(`grep -rl 'SWEEP_LAST_N\|corpus-tools-bench' tests/ tools/`), новый стенд не
заводить. Обязательные сценарии:

1. `SWEEP_LAST_N=08` → отказ кодом 2 с именем ручки. **И** отдельный сценарий:
   пустой набор версий (любой причиной) → код 5, а НЕ «все 0 версий измерены».
2. `SWEEP_LAST_N=0010` → ровно 10 версий, не 8.
3. Обломок `kit.XXXXXX`, из которого исполняется живой процесс, старше суток →
   каталог НА МЕСТЕ, строка «снимок кита НЕ убран», процесс жив.
4. Каталог версий с `.claude-patched-<хвост>`, новее настоящей версии →
   выбрана настоящая версия; каталог только из обломков → отказ 2 с названной
   причиной.
5. Два `_replace_backup` над одним backup → имена стадий различны (по `<pid>`);
   опубликованный backup побайтно равен ОДНОМУ из источников.
6. Стадия `probes-sync` с чужим переиспользованным номером (владелец с иным
   `lstart`) → `--diff` объявляет расхождение, прополка сносит стадию и владельца.
7. `CLAUDE_PATCH_SKIP_MODELS=true` → синхрон ПРОПУЩЕН; `SWEEP_SKIP_BUILD_PROBE=0`
   → зонд ИДЁТ; `KEEP_ROOT=0` → корень удалён; `KEEP_ROOT=ага` → отказ 2.
