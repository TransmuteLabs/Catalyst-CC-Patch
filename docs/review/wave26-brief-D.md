### D-2 (высокая). Маскировка смерти от сигнала в форк-запаске

`tools/sweep.sh:207`: `if ($child) { waitpid($child, 0); exit($? >> 8) }`.

ЗАМЕРЕНО контроллером: ребёнок под SIGKILL даёт сырой статус 9, `$? >> 8` = **0** —
обёртка рапортует УСПЕХ об убитом прогоне. Путь исполняется, когда запускающий pid
уже лидер группы, то есть при интерактивном запуске из терминала — основной
операторский путь.

Заменить на подъём сигнала в код: если `$? & 127` ненулевой — выходить
`128 + ($? & 127)`; иначе `$? >> 8`. Форма кодов 128+N — та же, что даёт bash.

### D-3 (высокая). Слитый трап отдаёт 0 на убитом прогоне

ЗАМЕРЕНО контроллером на этой машине:
* `trap … EXIT INT TERM` (слитый) → TERM даёт rc **0**, уборка исполняется;
* `trap … EXIT` (только выход) → TERM даёт rc **143**, уборка исполняется.

Слитая форма — дефект: убитый прогон зелен. Три носителя:
`tools/backup-divergence-probe.sh:59`, `tools/checks-on-image.sh:75`,
`scripts/kit-build.sh:52`.

Привести каждый к канонической форме кита (образец `tools/fetch-corpus.sh:80-82`):
```
trap __exit_guard EXIT
trap 'exit 130' INT
trap 'exit 143' TERM
```
`tools/corpus-tools-bench.sh:196` и `claude-patch-all.sh:407` несут ТОЛЬКО `EXIT` —
это по замеру ПРАВИЛЬНО, НЕ ТРОГАТЬ.

Если у файла нет часового `__DONE`, а `__exit_guard` на него опирается — сверься с
живым образцом того же файла и не выдумывай: часовой добавляется только если
`__exit_guard` этого файла его читает.

### D-4 (средняя). Запись lstart не проверяет непустоту

`tools/sweep.sh:360` пишет `printf '%s\t%s\n' "$$" "$(LC_ALL=C ps -o lstart= -p "$$" 2>/dev/null)"`
без проверки подстановки. Отказавший `ps` кладёт `PID\t`, и дверь `--stop` отказывает
ВЕСЬ прогон, объявляя «номер группы переиспользован» — диагноз неверен.

Снять метку в переменную, проверить непустоту. Пусто ⇒ файл `sweep.pgid` НЕ создавать,
`__PGID_OURS=0`, напечатать NOTE, что для этого прогона дверь `--stop` недоступна и
почему. Прогон при этом продолжается — отсутствие двери не повод его валить.

### D-5 (низкая-средняя). Неверный диагноз «лидер мёртв, группа жива»

`tools/sweep.sh:90-93`: когда `kill -0 -- -$pgid` проходит (группа жива), а
`ps -p $pgid` пуст (лидер мёртв), печатается заголовок «номер группы переиспользован,
это не наш прогон». Для этого случая он ложен.

Развести два случая явными сообщениями: «номер группы переиспользован» — только когда
`ps` ДАЛ метку и она НЕ совпала; «лидер группы мёртв, группа жива — дверью не
остановить, нужен ручной сигнал по группе» — когда `ps` пуст. Код возврата в обоих
случаях прежний, сигнал не слать.

### D-6 (низкая). Наследный `.part.XXXXXX` не убирается никогда

`tools/fetch-corpus.sh:105-111`: прополка требует ЧИСЛОВОЙ суффикс
(`[[ "$__ppid" =~ ^[0-9]+$ ]] || continue`), поэтому обломки прежней формы
`.part.XXXXXX` (mktemp, убран волной 25) лежат вечно.

Прополка идёт ПОД замком наполнителя, а замок сериализует писателей на весь прогон ⇒
любой `.part.` с НЕчисловым суффиксом, видимый под замком, — сирота по построению.
Убирать его безусловно, с тем же сообщением, что и для мёртвого pid.

### D-7 (низкая). Исключение переписи замков слишком широко

`tools/lock-probe.sh:309` вычитает из переписи ЛЮБУЮ строку вида `:[0-9]*:  '` в
ЛЮБОМ файле. Настоящее взятие замка, отформатированное с двумя пробелами и кавычкой,
выпадет из переписи молча.

Сузить исключение до файла, где живут таблицы мутаций (`tools/corpus-tools-bench.sh`),
а не применять ко всему киту.

### D-8 (низкая). Число цифр без границы

`validated_nonnegative_integer` в `claude-patch-all.sh` принимает 20-значное число,
которое в bash-арифметике заворачивается в отрицательное. Ограничить величину
(сравнением значения, не длины строки) и объявить границу в сообщении отказа.

### D-9 (низкая-средняя). Фолбэк окна может превысить ёмкость маршрута

`set-model-costs.py` ~`:169-202`: при `routed − reply_headroom() <= 0` лестница
проваливается к `limit.input` / `limit.context − headroom`, которые могут быть БОЛЬШЕ
реального маршрута (routed=32000 → объявлено 116000). Отсечь фолбэк СВЕРХУ значением
`routed`: объявленное окно не вправе превышать ёмкость маршрута ни на одной ветке.

## Зубы — обязательная часть, не приложение

Каждое новое утверждение принимается ТОЛЬКО с названной мутацией, которая краснит
СВОЙ сценарий СВОЕЙ причиной (подстрока `MUT_CAUSE` в `LAST_EVID`). Мутация обязана
ПРИМЕНИТЬСЯ (якорь существует и единственен) и ДОЕХАТЬ до объекта.

Распределение по стендам:
* D-2, D-4, D-5, D-6, D-7 → `tools/corpus-tools-bench.sh` (он уже меряет `sweep.sh`,

  `EXPECTED_MUTATIONS`, добавить записи во ВСЕ ПЯТЬ таблиц `MUT_*` (FILE/PAT/REP/
  SCENARIO/CAUSE) — длины таблиц сверяются `check_mut_tables`.
* D-9 → `tools/costs-bench.py`.
* D-1, D-3, D-8, D-10 → `tools/checks-teeth.py`, если утверждение выражается проверкой
  реестра; иначе объяви в отчёте, ПОЧЕМУ зуб невозможен, и запинь свойство ПО ФОРМЕ.
* D-11 — проза, зуб не нужен; но гейт чисел (`python3 tools/docnum-bench.py`) обязан

D-2 меряется так: сценарий поднимает прогон по пути форк-запаски (запускающий pid —
лидер группы), убивает ребёнка СИГНАЛОМ и требует код `128+N`, а не 0. Если поднять
этот путь в стенде не выходит — НЕ подделывай: объяви «свойство стенд исполнить не
