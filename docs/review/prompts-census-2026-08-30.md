# Перепись системных промтов: своих правок ноль

Замер 2026-08-30, дом слоя — `~/.tweakcc/system-prompts/*.md` (847 файлов) и
`~/.tweakcc/prompt-data-cache/prompts-<ver>.json`.

## Итог

Своих правок системных промтов у нас **нет ни одной**. Все 847 файлов —
стоковые тексты разных дат, отличающиеся от снимка только формой.

Числа, называвшиеся по ходу работы (27, 119, 124, 83, 13, 2), неверны все:
каждое снимало один слой шума и упиралось в следующий.

## Четыре слоя шума, каждый из которых читается как правка

1. **Экранирование.** Кэш снимков хранит сырую JS-форму (`can\'t`), рабочая
   копия `.md` — готовый текст (`can't`).
2. **Форматирование JS внутри `${...}`.** Снимок распрямлён
   (`${ X ? \`…\` : "" }`), рабочая копия сжата (`${X?\`…\`:""}`). Это НЕ
   изменение апстрима: на `agent-prompt-pull-request-creation.md` наша
   «правка» совпала байт в байт с изменением апстрима 2.1.235 → 2.1.251.
3. **Имена-заполнители.** tweakcc генерирует их заново в каждом снимке
   (`GET_MAX_TIMEOUT_MS` → `MAX_TIMEOUT_MS_FN`). Гасить их надо именами из
   ОБЕИХ карт — базовой версии и целевой; по одной базовой переименование
   остаётся видимым и читается как правка.
4. **Имена из поколения, которого нет ни в одном скачанном снимке**
   (`ONE_OFF_ENABLED` в `agent-prompt-schedule-slash-command.md`).

## Рабочий нормализатор

Заменить все имена из `identifierMap` обеих версий на один символ, затем снять
все пробелы и обратные косые. Прибор проверять отдельно: среди 983 имён
заполнителей есть словарные (`MODEL`, `TASK`, `TOOL`, `TOOLS`, `FALSE`) — их
гашение способно уравнять разные тексты, поэтому имена берутся из карты
КОНКРЕТНОГО промта, а не из общего множества.

## Почему нельзя опереться на критерий самого tweakcc

`systemPromptOriginalHashes.json` как независимая проверка НЕ годится — он
сломан по построению, см. задачу «мёртвая ветка авто-обновления промтов».
Замер: md5 не совпадает НИ У ОДНОГО из 847 файлов. Разложение — у 215
содержимое равно реконструкции из снимка, но индекс от неё отличается; у 493
наоборот; пересечение пусто. Причина: `storeHashes()` пишет запись по ключу
`id-версия` только если её ещё нет, а апстрим перегенерирует снимки с другими
именами заполнителей. Следствие: `isModified` истинно всегда, ветка
«пользователь не менял → обновить автоматически» недостижима, и каждый подъём
версии даёт «конфликты» (на 2.1.250 их 36) при полном отсутствии правок.

## Радиус для образа: нулевой

Промт со съехавшим именем форк ПРОПУСКАЕТ, а не вписывает — это их защита от
#900. На сборке 2.1.250 пропущено 3 промта с названной причиной («replacement
references ONE_OFF_ENABLED … not found in cli»). Ещё 46 промтов не нашли своего
места в `cli.js` (апстрим переписал текст, копия старая) — байты образа при
этом тоже не трогаются.

## Исход: обе поломки индекса починены в форке

`TransmuteLabs/Catalyst-tweakcc` a89c9da, пин кита поднят
`dd0cadb` → `a89c9da`.

1. **Решение «трогал ли пользователь файл» больше не спрашивает индекс.**
   Базовая версия реконструируется из снимка (конфликтная ветка это и так
   делала для своей базы диффа), хвостовые переводы строки нормализуются.
   Индекс остался запасным путём на случай, когда старый снимок не достать —
   там «считать изменённым» безопаснее: затереть настоящую правку хуже одного
   лишнего конфликта. `downloadStringsFile` получил память в процессе: решение
   теперь спрашивает снимок на каждый устаревший файл, а не на каждый конфликт.

2. **Индекс применённых хэшей пишется один раз и атомарно.**
   Было: `setAppliedHash` внутри цикла — чтение всего файла, разбор, мутация,
   перезапись целиком, сотни раз за один `--apply`, каждая запись усекает цель
   на месте. Стало: накопление в цикле, одна запись после него через
   `setAppliedHashes`, оба писателя индекса — через временный файл рядом с
   целью и переименование.

Замер эффекта до сборки: из 799 локальных файлов, бывших конфликтом
безусловно, 676 теперь обновятся сами, 123 останутся конфликтом (тело другого
поколения форматирования — консервативный и правильный ответ). Проверяемое
предсказание на следующую сборку: падает и число конфликтов, и число «Could
not find system prompt».
