## L-1. Высшая важность — следующий свип удаляет снимок из-под живого процесса

**Координаты:** `tools/sweep.sh:373-374`, `tools/sweep.sh:386-391`, `tools/sweep.sh:446-459`, `tools/sweep.sh:983-984`

Прополка обломков:

    for __stale in "$STATE"/kit.?????? ...
    rm -rf "$__stale" && echo "SWEEP убрал обломок прошлого прогона: $__stale"

Проверка живых процессов выполняется ТОЛЬКО ПОЗЖЕ:

    alive=$(...)
    if [[ -n "$alive" ]]; then ... exit 3

При этом конвейер намеренно запускается без дескриптора замка свипа:

    bash "$HERE/claude-patch-all.sh" ... 8>&-

**Что происходит.** После `SIGKILL` лидера дочерний `claude-patch-all.sh` может
продолжать исполняться из `kit.XXXXXX`, не удерживая замок свипа. Через сутки
следующий свип получает свободный замок, удаляет каталог и лишь ЗАТЕМ
обнаруживает живого ребёнка.

**Последовательность:** создать `STATE/kit.ABCDEF` с исполняющимся из него
`claude-patch-all.sh`; оставить процесс живым, mtime каталога сделать старше
суток; запустить `tools/sweep.sh` на копии кита с отдельным `SWEEP_STATE_DIR`.

**Измерено (изолированная проба):** `SWEEP_RC 3`; строка «SWEEP убрал обломок
прошлого прогона: .../kit.ABCDEF»; затем «SWEEP ОТКАЗ: живы процессы чужого
прогона конвейера»; процесс после прогона оставался жив; снимка на диске уже
не было.

**Сломанное свойство.** Гарантия «снимок сносится только когда из него никто не
исполняется» действует на штатный хвост и trap, но не на уборку следующего
запуска.

## L-2. Высокая важность — `.claude-patched-*` принимается за установленный бинарник

**Координаты:** `claude_patch.py:539-540`, `claude_patch.py:301-307`, `claude_patch.py:501-503`

Временный файл создаётся прямо в каталоге версий:

    tempfile.mkstemp(prefix=".claude-patched-", dir=target.parent, ...)

Fallback-фильтр исключает только СУФФИКСЫ:

    skip = (".orig", ".staging", ".restore", ".repair", ".new", ".tmp", ".bak", ".download")
    return max(cands, key=lambda p: p.stat().st_mtime)

После выбора файла с маркером патчер объявляет работу сделанной:

    if has_marker(target, ROUTING_MARKER):
        info("Already patched — nothing to do.")
        return

**Что происходит.** Если первый процесс умер после записи маркера во
`.claude-patched-*`, но до `os.replace(tmp, target)`, временный файл остаётся
НОВЕЙШИМ файлом каталога версий. При отсутствии пригодного launcher второй
запуск без аргументов выбирает именно его.

**Измерено:** на изолированном каталоге версий реальный код выбрал
`.claude-patched-deadbeef`, напечатал «Already patched — nothing to do.» и
оставил настоящий `2.1.251` без изменений.

## L-3. Средняя важность — оборванная запись пробы публикуется под конечным именем

**Координаты:** `tweakcc-patch.js:2498`, `judge/validate.py:104-107`, `judge/validate.py:581-583`, `judge/compact.py:245-255`

    await __jfs.writeFile(__jdir+"/records/"+__n,__out);

Читатель принимает все конечные имена (`*.json` + `*.json.gz`) и разбирает их
строго; `compact.py` повреждённый исходник не изолирует, печатает «ПРОПУЩЕНО
(архив не читается)» и возвращает 0.

**Измерено:** `validate.py run` вернул 1 с `JSONDecodeError`; `compact.py` вернул
0 и оставил повреждённый файл на месте; следующий `run` снова падает на том же
входе.

**Сломанное свойство.** Конечное имя не означает завершённую запись. Один
оборванный вызов становится постоянным входом следующих измерений и блокирует
весь `run`.

## L-4. Высокая важность — частичная копия в доказательную базу считается завершённой

**Координаты:** `judge/validate.py:524-539`, `judge/validate.py:551-559`

    Идемпотентно -- повторная разметка той же записи ничего не переписывает.
    if not os.path.exists(target):
        shutil.copy2(candidate, target)
    return target

Порядок заявлен как исключающий метку без записи: «Копия ДО записи метки: метка
без записи -- это указатель в пустоту».

**Что происходит.** `shutil.copy2` пишет прямо под конечным именем. После смерти
в середине копии target существует, поэтому повторный `keep_labelled()`
отказывается его переписывать и возвращает путь как успешный.

**Измерено:** реальный CLI вернул 0, напечатал «запись унесена в дом
доказательной базы», дописал валидную метку и оставил target усечённым.

**Сломанное свойство.** Обещанный порядок «сначала доказательство, потом метка»
проверяет только СУЩЕСТВОВАНИЕ имени, а не завершённость копии.

## L-5. Высокая важность — оборванный хвост `labels.jsonl` поглощает следующую метку

**Координаты:** `judge/validate.py:113-125`, `judge/validate.py:555-556`, `judge/adjudicate.py:342-349`

    Одна битая строка теряет ОДНУ метку и называет себя.

Запись — простой append:

    with open(LABELS_PATH, 'a', encoding='utf-8') as fh:
        fh.write(json.dumps(item, ...) + '\n')

**Что происходит.** Если оборванный хвост не оканчивается `\n`, следующий append
не начинает новую физическую строку — он приклеивает полноценную следующую метку
к фрагменту, и читатель пропускает всю склеенную строку. Толерантный читатель
теряет не только оборванный объект, но и ПЕРВУЮ СЛЕДУЮЩУЮ успешно записанную
метку.

**Измерено:** второй `label` вернул 0 и напечатал полный JSON; файл содержал одну
физическую склеенную строку; `list` показал для второй записи «нет метки».

## L-6. Высокая важность — временный файл `compact.py` вытесняет настоящую запись

**Координаты:** `judge/compact.py:221-232`, `tweakcc-patch.js:2535-2540`

Проблема прямо ОПИСАНА в комментарии, но не устранена:

    Суффикс .tmp.<pid> действительно не подпадает под НАШ глоб *.json
    ... но в горизонт ядра он попадает:
    tmp занимает место, вытесняя настоящую запись
    tmp = gz + f'.tmp.{os.getpid()}'

Фильтр ядра исключает лишь `.gz`:

    .filter((__x)=>__x!==__n&&!__x.endsWith(".gz"));
    if(__ls.length>=__jkeep){__ls.sort(); ... unlink(...__old)

**Измерено (окно 2):** кандидатами стали `old.json` и `old.json.gz.tmp.999999`;
жертвой стал `old.json`; после прохода остались current и tmp.

**Сломанное свойство.** `records_keep=N` не сохраняет N настоящих горячих
записей. Остаток убитого compactor принимается за данные и вызывает необратимую
потерю полноценной записи.

## L-7. Средняя важность — два `_replace_backup` делят фиксированное `.new`

**Координаты:** `claude_patch.py:469-480`

    tmp = backup.with_name(backup.name + ".new")
    shutil.copy2(src, tmp)
    os.replace(tmp, backup)

Временное имя не содержит PID. Один процесс может переименовать `.new` в backup,
пока второй продолжает писать через уже открытый дескриптор.

**Измерено:** процесс B завершился успешно; процесс A получил
`FileNotFoundError`; конечный backup содержал первую половину B и вторую
половину A. (Первая попытка пробы не стартовала из stdin из-за spawn-режима
Python 3.14; повтор через fork воспроизвёл расхождение.)
