# Ревью-пакет волны 34b — двери уровня tweakcc, зубы гейта чисел

## Предмет

Дифф незакоммичен, дерево кита `Catalyst-CC-Patch`, база — коммит `57b4044`.
Смотреть: `git -C <кит> diff` плюс НОВЫЙ (untracked) файл
`tools/tweakcc-expected-applied.txt` и `tools/lockfd-check.py`.

## Что чинилось

1. **#58.** Строка `tweakcc: легло N правок` печаталась и ничем не гейтилась.
   Заведённая на неё дверь пинила СУММУ, у половин которой РАЗНЫЕ владельцы:
   слой кода — «версия апстрима × наш форк tweakcc»; слой накладок промтов —
   каталог пользователя `~/.tweakcc/system-prompts/`. Суммарный пин отказывал
   на 2.1.259 («объявлено 34, легло 33»).
   Починка: два числа. Код — ДВУСТОРОННЯЯ дверь (меньше и больше объявленного
   = отказ). Накладки — ПОЛ (просадка = отказ, рост = никогда). Маркер
   `нет-слоя` = отказ на любое ненулевое легшее ИЛИ ненайденное. Пол не число
   и не маркер = отказ. Строки версии нет = отказ с ОБОИМИ числами и готовой
   строкой. Носитель — `__tw_check_applied_level()` в `claude-patch-all.sh`.
2. **Третий канал.** Накладка, чей текст разошёлся с образом, печатает
   `Could not find system prompt "X" in cli.js` — ни галочки, ни крестика.
   Сверка непроходов читает только `✗` и этих промахов не видела вовсе (на
   2.1.259 их 24). Теперь считаются и поимённо называются в логе; НЕ гейтятся
   намеренно (потолок воспроизвёл бы тот же дефект двух владельцев).
3. **Зубы гейта чисел.** У счётчиков `tools/build-path-probe.sh` было два дома
   (константы зонда + README) и НИ ОДНОЙ строки мутаций, доказывающей, что
   гейт заметит их расхождение. Добавлены `D43`/`D44` в
   `tools/docnum-mutations.tsv`, счёт стенда 42 → 44 по всем домам.
4. Сценарий `n` зонда `build-path-probe.sh` был недостижим по умолчанию:
   строка `CASES` его не содержала, хотя README его объявлял.

## Авторские вопросы (отвечать по каждому, с file:line)

1. **Может ли просадка слоя КОДА остаться незамеченной?** Счётчики
   `__tw_applied_code_level` / `__tw_applied_prompt_level` делят строки `✓` по
   типовому префиксу. Сверь образцы с ЖИВЫМ выводом tweakcc в логах урожая:
   есть ли строка `✓`, которая попадёт не в свой слой (или ни в один)? Если
   правка кода начнёт печататься с двоеточием в имени — куда она уедет?
2. **Слепая ручка.** `CLAUDE_PATCH_ALLOW_TWEAKCC_FAILURES=1` гасит дверь
   ранним `return 0`. Найди ВСЕХ потребителей вердикта сборки (`tools/sweep.sh`,
   `tools/corpus-tools-bench.sh`, README): не считает ли кто-то слепой прогон
   прогоном с проверенным уровнем?
3. **Отказ по отсутствующей строке** печатает готовую строку для вставки.
   Она четырёхколоночная (новый формат) или трёхколоночная (старый)? Проверь
   ФОРМАТ печати, а не намерение.
4. **Ветка `нет-слоя`** сегодня не выбрана ни одной строкой дома. Достижима
   ли она вообще и что её краснит?
5. **Перечень ненайденных накладок** режется `cut -c1-200`. Что произойдёт с
   многобайтовой границей? Это дефект вывода или косметика — назови конкретный
   вход.
6. **Док-правда.** Утверждения в README (строка про `tools/build-path-probe.sh`
   и про `docnum-bench`) и в шапке `tools/tweakcc-expected-applied.txt` —
   сверь КАЖДОЕ с кодом. Особое внимание к связкам «всегда», «никогда»,
   «любой»: они добавлены при сжатии.
7. **Вакуумность зубов.** Мутации `D43`/`D44` — краснят ли они СВОЮ причину, и
   можно ли убить свойство, не тронув их якорь?
8. **Числа в новом файле данных** (13/14/19/20/22/24/33/36/46) — не ловит ли их
   гейт чисел как объявленные счётчики с владельцем? Если файл вне области
   гейта — назови, где эта область задана.
