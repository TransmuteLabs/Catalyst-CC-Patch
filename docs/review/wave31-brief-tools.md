## 1. Общий тип аргумента вместо трёх разных недосмотров (K-5, K-7, K-13, K-14)

Один класс: числовой аргумент принимается `type=int`/`type=float` и дальше

Дом общего правила — `judge/replay.py`: его импортируют И `validate.py`, И
`adjudicate.py` (проверено: `judge/adjudicate.py:23`, `judge/validate.py:28`).
Новый файл не заводить.

Добавить в `replay.py` два `argparse`-типа, каждый бросает
`argparse.ArgumentTypeError` с ИМЕНЕМ ручки и причиной (argparse превратит это в
код 2 — тот же код, которым соседи уже отвергают `--jobs`/`--repeat`):

* `nonneg_int(s)` — целое ≥ 0. Ноль сохраняет свой действующий смысл «без
  потолка» у `--limit`.
* `bounded_float(name, lo, hi)`-фабрика — конечное число (не `nan`, не `inf`) в
  отрезке.

Применить:

* `--limit` в `judge/validate.py`, `judge/adjudicate.py`, `judge/replay.py` →
  `nonneg_int`. Сегодня `type=int` пропускает минус, а три читателя пишут
  `files[-limit:]`: измерено на пяти файлах — `--limit=-1` МОЛЧА выкидывает
  самую старую запись, `--limit=-5` даёт пустой список, и прогон объявляет
  код 5 «записи не найдены», хотя записи на диске есть.
* `judge/validate.py:666` `--timeout` → `bounded_float('--timeout', 0.001, 86400)`.
  Верхняя граница выбрана не для красоты: `timeout_ms = 240000` из соседнего
  toml, скопированный в `--timeout 240000`, — это 240000 СЕКУНД (~67 часов), и
  потолок в сутки превращает эту описку в громкий отказ вместо прогона, который
  никогда не кончится. Сообщение об отказе обязано назвать единицы: «`--timeout`
  в СЕКУНДАХ; `timeout_ms` в соседнем toml — в миллисекундах».

  выглядят штатным проходом. Ноль остаётся буквальным («старше нуля часов») —
  это решение контроллера, не менять.

### Правка 4 — граница строки в labels.jsonl (L-5)

* `judge/replay.py:77-104` — `append_jsonl(path, payload)`: если файл существует,
  непуст и последний байт не `\n`, полезная нагрузка предваряется `\n`;
  проверка и дозапись — один вызов write на весь payload. В докстринге
  названа связка с ядром: «Контракт общий с ядром кита (tweakcc-patch.js,
  дозапись journal.jsonl, волна 31 бриф 1): границу ВОССТАНАВЛИВАЕТ писатель,
  читатель остаётся толерантным».
* `judge/validate.py:633-638` — `command_label` дописывает метку через
  `replay.append_jsonl(LABELS_PATH, … + '\n')`.
* `judge/adjudicate.py:355` — батч меток дописывается тем же
  `replay.append_jsonl(LABELS_PATH, batch)`; измеренный комментарий о
  недробимости write и об отсутствии замка сохранён и дополнен строкой о
  восстановлении границы.
* Комментарии толерантных читателей (`judge/validate.py:119-130`,
  `judge/adjudicate.py:186-199`) переписаны под новый инвариант: «одна битая
  строка теряет ОДНУ метку» — теперь следствие контракта писателей, а не
  обещание.

Мутация (RED, сырой вывод):

```
judge-tools-bench: МУТАЦИЯ M52: RED (сценарий 44)   # восстановление границы вырвано (if False)
```

Причина: «граница строки не восстановлена». Сценарий 44: хвост
`{"rec": "stale", …` без `\n` + новый `label` → в файле ДВЕ физические строки,
новая метка разбирается и видна в `list` (`labels_by_record`); вызов
адъюдикатора закреплён формой
(`replay.append_jsonl(LABELS_PATH, batch)` в тексте adjudicate.py) — его
штатный прогон требует сети, приём пина формы объявлен в докстринге сценария
(тот же, что у сценариев 17-18, 20, 27).
