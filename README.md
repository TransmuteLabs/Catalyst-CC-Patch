# Набор патчей Claude Code

Конвейер, который правит локально установленный образ Claude Code и ставит в
него три механизма: работу через нескольких поставщиков моделей, **судью
диспатчей** (проверяет каждый вызов субагента до запуска — готов ли бриф,
соразмерна ли модель, нужен ли веер) и **наблюдателя за флотом** (ловит случай
«главный цикл работает, субагенты простаивают», который никакая статистика
диспатчей не видит по устройству). Оба механизма делят одно ядро и настраиваются
одним файлом `probes.toml`.

Патч живёт в самом образе, а не в хуке: хук видит не всё и обходится, врезка —
нет. Ничего не ставится, если хоть одна из 78 проверок не прошла, и переключение
на новую сборку происходит только после дымового гейта.

> **Граница.** Репозиторий содержит ТОЛЬКО наши файлы. Образ Claude Code —
> проприетарное ПО Anthropic, здесь он не распространяется: конвейер читает тот,
> что уже стоит у вас. Допустимость модификации определяется вашим соглашением с
> Anthropic, а не этой лицензией. Применяете на свой риск: сломанный образ
> чинится переустановкой, но время вы потеряете.

Проверено на **2.1.239** (macOS arm64). Это инструмент под mac: здесь он
живёт и здесь проверяется. `claude_patch.py` по конструкции умеет и linux с
windows (пропатченный JS-бандл на всех платформах ОДИН, различается только
контейнер — распаковка, перепаковка, подпись), но эти дороги не прогонялись и
проверенными не считаются.

Патчи находят свои места структурными регулярными выражениями, поэтому обычно
переживают смену версий; при непопадании конвейер падает громко и НИЧЕГО не
ставит. На 2.1.239 непопаданий было два (адаптер вокруг вызова инструмента и
имя `$jS`, вклеенное в шаблон без экранирования) — оба починены, см.
`docs/judge-architecture.md` §14.

## Что нужно

- `node` (на нём работает tweakcc), `python3`, сеть для `npx tweakcc`
- macOS: подпись. Скрипт берёт первую доступную идентичность
  (`security find-identity -v -p codesigning`); переопределяется переменной
  `CLAUDE_PATCH_SIGN_ID`. Без корректной подписи связка ключей отдаёт
  «Not logged in».

## Как пользоваться

```bash
bash claude-patch-all.sh                  # пропатчить текущую установку
bash claude-patch-all.sh --update         # поставить свежий Claude Code и пропатчить
bash claude-patch-all.sh --update 2.1.238 # конкретную версию
bash claude-patch-all.sh --only-ours      # без патчей самой tweakcc
```

**Если патчится бинарник, который ПРЯМО СЕЙЧАС исполняет твою сессию** —
собирай в сторону и подменяй переименованием, иначе можно убить живой процесс:

```bash
V=~/.local/share/claude/versions/2.1.238
cp -p "$V.orig" "$V.staging"
bash claude-patch-all.sh --target "$V.staging"
mv "$V.staging" "$V"      # атомарно; действует со следующего запуска
```

Порядок нарушать нельзя: `tweakcc --apply` восстанавливает бинарник из своей
резервной копии, поэтому наши патчи всегда идут ПОСЛЕ неё, а любой запуск
tweakcc (включая её TUI) требует повторного прогона этого скрипта.

## Что делают патчи (78 проверок)

Маршрутизация и модели: `claude-*` идут на подписку, остальные на прокси;
произвольные модели у агентов; обнаружение моделей шлюза без токена; цены и
окна контекста по моделям; прокси-полоса переживает истёкший вход; диспатч
сохраняет модель и усилие; восстановление сессии не теряет прокси-модель.

Интерфейс и живучесть: значок модели у субагента, тип и модель в списке
агентов, цвет шеврона, поиск по сессиям дочитывает хвост, оборванный поток
повторяется вместо половинчатого ответа, интерактивный режим координатора.

Перенесено из tweakcc (её собственный набор на 2.1.238 не применяется —
собранный ею бандл не разбирается): троттлинг статусной строки 300→500 мс;
снятие ОБОИХ отказов при euid 0 (tweakcc снимает только первый); чтение
`AGENTS.md` и других имён вместо `CLAUDE.md`.

Судья вызовов субагентов: раскладка текущего хода; консультация перед
диспатчем ПУЛОМ МОДЕЛЕЙ САМОГО КЛИЕНТА (claude-* — подписочная полоса,
остальное — прокси; свой HTTP-путь только явным адресом); журнал каждой консультации; лестница попыток со своими порогом,
бюджетом, усилием и размером ленты у каждой ступени; лента уходит массивом
записей с происхождением, а не размеченными строками; подрезка ленты вытесняет
что угодно РАНЬШЕ реплик человека, но закреплённое ограничено долей ленты;
вывод локальной команды не носит метку человека, а аргументы слэш-команды —
носят; резюме компакции закрепляется отдельной долей как единственный носитель
стоячих распоряжений после сжатия ленты; ответ без вердикта при
2xx считается отказом ступени; сорвавшаяся ступень сохраняет СВОЮ причину и
свой ответ (иначе следующая затирала диагноз); режим `fail_closed` — отмена
вызова, когда вердикта не дала ни одна ступень, и такая отмена названа в
журнале своим исходом; полная запись каждой
консультации рядом с журналом; проектный слой настройки.

Наблюдатель за флотом: второй потребитель ТОГО ЖЕ ядра, что и судья, — совпадают
слои настройки, сборка ленты, канал к модели, лестница, журнал и разбор вердикта;
различий ровно четыре, и они же параметры (когда зовут, что показывают, каким
промтом, как реагируют). Зовётся на вызове инструмента, а не на диспатче, и
отвечает не отменой, а вкладкой напоминания в ход — он НЕ гейт. Половина его
работы — молчать: промт начинается с поиска причины, по которой веера сейчас
быть не должно (человек запретил, велел сперва закончить, работа неделима, луп
пишет бриф), и запретом считается только запись `src":"user"`. Два отсева: по
памяти до всякого ввода-вывода (каждый отказ называет миг, раньше которого не
может смениться) и по настройкам — окно, порог, период покоя.

Системный промпт: главному лупу вклеивается ПРАВИЛО — отменённый диспатч несёт
причину, причина есть указание к исправлению, неизменный повтор запрещён. Без
`CLAUDE_JUDGE` вклейки нет; субагентам она не идёт.

## Настройки, которые патч НЕ делает (и не должен)

В `~/.claude/settings.json`, раздел `env`:

```json
"CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS": "1000000"
```

Это штатная переменная самого Claude Code — она перебивает умолчание 25 000
токенов на чтение файла, и патчить ради этого байты не нужно. Отдельный предел
по РАЗМЕРУ (262 144 байта) переменной не управляется и остаётся.

Судья по умолчанию выключен. Чтобы включить, туда же:

```json
"CLAUDE_JUDGE": "1"        // только наблюдение и журнал
"CLAUDE_JUDGE": "enforce"  // отменять неудачные вызовы
```

Свои правила проект излагает сам, в ближайшем над рабочим каталогом
`.claude/probes/`: ключи в `probes.toml` под таблицей `[probe.judge]`, текст —
в `judge/prompt.extra.md`. Судья по-прежнему ничего не знает о проекте — он
судит событие, логику и правила.

Записи судейств копятся несжатыми и складываются в архив суточным проходом.
Агент launchd (образец — `com.transmutelabs.judge-compact`, 04:07) надёжнее
crontab: пропущенный из-за сна запуск launchd отрабатывает после пробуждения.

Наблюдатель за флотом тоже выключен по умолчанию и включается своей
переменной:

```json
"CLAUDE_IDLE": "1"
```

Пороги — в `~/.claude/probes/probes.toml` под таблицей `[probe.idle-watch]`:
`window_min` (окно счёта), `threshold` (сколько диспатчей за окно считается
достаточным) и `cooldown_min` (как часто напоминание вообще возможно).
Проектный слой — `.claude/probes/`, теми же правилами слияния, что у судьи.

Подробности — `judge/README.md` и `idle-watch/README.md`.

## Грабли, проверенные на себе

- **Совпадение образца ≠ работающий образ.** Один неэкранированный перевод
  строки внутри вставленного литерала оставлял все проверки зелёными, а
  бинарник умирал на `SyntaxError`. Поэтому в конвейере есть жёсткий дымовой
  прогон: образ запускается и обязан напечатать строку версии, иначе лаунчер не
  переключается. Именно он ловит такие случаи.
- **`$(cmd | head -1)` в проверке выбрасывает код возврата** — нерабочий образ
  отчитывается успехом. Статус захватывать отдельно.
- **tweakcc пакует бандл как БАЙТЫ**: не-ASCII в литерале вставки приезжает в
  двойной кодировке. Эмитировать `\uXXXX`.
- **Проверка вида `var X=500` даёт ЗЕЛЁНЫЙ на чистом образе** — таких констант
  там шесть. Любую новую проверку прогонять против ЧИСТОГО образа: она обязана
  падать.
- **Лаунчер переключать только ПОСЛЕ проверок.** Между «поставлен чистый» и
  «пропатчен» есть окно: сессия, стартовавшая в нём, уйдёт на прокси с
  подписочным токеном и умрёт.
