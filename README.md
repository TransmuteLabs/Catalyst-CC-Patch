# Набор патчей Claude Code

Проверено на **2.1.237** (macOS arm64). Патчи находят свои места
структурными регулярными выражениями, поэтому переживают смену версий; при
непопадании конвейер падает громко и НИЧЕГО не ставит.

## Что нужно

- `node` (на нём работает tweakcc), `python3`, сеть для `npx tweakcc`
- macOS: подпись. Скрипт берёт первую доступную идентичность
  (`security find-identity -v -p codesigning`); переопределяется переменной
  `CLAUDE_PATCH_SIGN_ID`. Без корректной подписи связка ключей отдаёт
  «Not logged in».

## Как пользоваться

```bash
bash claude-patch-all.sh                  # пропатчить текущую установку
bash claude-patch-all.sh --update         # поставить свежий Claude Code и пропатчить
bash claude-patch-all.sh --update 2.1.237 # конкретную версию
bash claude-patch-all.sh --only-ours      # без патчей самой tweakcc
```

**Если патчится бинарник, который ПРЯМО СЕЙЧАС исполняет твою сессию** —
собирай в сторону и подменяй переименованием, иначе можно убить живой процесс:

```bash
V=~/.local/share/claude/versions/2.1.237
cp -p "$V.orig" "$V.staging"
bash claude-patch-all.sh --target "$V.staging"
mv "$V.staging" "$V"      # атомарно; действует со следующего запуска
```

Порядок нарушать нельзя: `tweakcc --apply` восстанавливает бинарник из своей
резервной копии, поэтому наши патчи всегда идут ПОСЛЕ неё, а любой запуск
tweakcc (включая её TUI) требует повторного прогона этого скрипта.

## Что делают патчи (35 проверок)

Маршрутизация и модели: `claude-*` идут на подписку, остальные на прокси;
произвольные модели у агентов; обнаружение моделей шлюза без токена; цены и
окна контекста по моделям; прокси-полоса переживает истёкший вход; диспатч
сохраняет модель и усилие; восстановление сессии не теряет прокси-модель.

Интерфейс и живучесть: значок модели у субагента, тип и модель в списке
агентов, цвет шеврона, поиск по сессиям дочитывает хвост, оборванный поток
повторяется вместо половинчатого ответа, интерактивный режим координатора.

Перенесено из tweakcc (её собственный набор на 2.1.237 не применяется —
собранный ею бандл не разбирается): троттлинг статусной строки 300→500 мс;
снятие ОБОИХ отказов при euid 0 (tweakcc снимает только первый); чтение
`AGENTS.md` и других имён вместо `CLAUDE.md`.

Судья вызовов субагентов: раскладка текущего хода; консультация перед
диспатчем ПУЛОМ МОДЕЛЕЙ САМОГО КЛИЕНТА (claude-* — подписочная полоса,
остальное — прокси; свой HTTP-путь только явным адресом); журнал каждой консультации; лестница попыток со своими порогом,
бюджетом, усилием и размером ленты у каждой ступени; лента уходит массивом
записей с происхождением, а не размеченными строками; ответ без вердикта при
2xx считается отказом ступени; полная запись каждой консультации рядом с
журналом; проектный слой настройки.

Системный промпт: главному лупу вклеивается ПРАВИЛО — отменённый диспатч несёт
причину, причина есть указание к исправлению, неизменный повтор запрещён. Без
`CLAUDE_JUDGE` вклейки нет; субагентам она не идёт.

## Настройки, которые патч НЕ делает (и не должен)

В `~/.claude/settings.json`, раздел `env`:

```json
"CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS": "1000000"
```

Это штатная переменная самого Claude Code — она перебивает умолчание 25 000
токенов на чтение файла, и патчить ради этого байты не нужно. Отдельный предел
по РАЗМЕРУ (262 144 байта) переменной не управляется и остаётся.

Судья по умолчанию выключен. Чтобы включить, туда же:

```json
"CLAUDE_JUDGE": "1"        // только наблюдение и журнал
"CLAUDE_JUDGE": "enforce"  // отменять неудачные вызовы
```

Свои правила проект излагает сам, в ближайшем над рабочим каталогом
`.claude/judge/` (`config.json`, `prompt.extra.md`). Судья по-прежнему ничего не
знает о проекте — он судит событие, логику и правила.

Записи судейств копятся несжатыми и складываются в архив суточным проходом.
Агент launchd (образец — `com.maratkarimov.judge-compact`, 04:07) надёжнее
crontab: пропущенный из-за сна запуск launchd отрабатывает после пробуждения.

Подробности — `judge/README.md`.

## Грабли, проверенные на себе

- **Совпадение образца ≠ работающий образ.** Один неэкранированный перевод
  строки внутри вставленного литерала оставлял все проверки зелёными, а
  бинарник умирал на `SyntaxError`. Поэтому в конвейере есть жёсткий дымовой
  прогон: образ запускается и обязан напечатать строку версии, иначе лаунчер не
  переключается. Именно он ловит такие случаи.
- **`$(cmd | head -1)` в проверке выбрасывает код возврата** — нерабочий образ
  отчитывается успехом. Статус захватывать отдельно.
- **tweakcc пакует бандл как БАЙТЫ**: не-ASCII в литерале вставки приезжает в
  двойной кодировке. Эмитировать `\uXXXX`.
- **Проверка вида `var X=500` даёт ЗЕЛЁНЫЙ на чистом образе** — таких констант
  там шесть. Любую новую проверку прогонять против ЧИСТОГО образа: она обязана
  падать.
- **Лаунчер переключать только ПОСЛЕ проверок.** Между «поставлен чистый» и
  «пропатчен» есть окно: сессия, стартовавшая в нём, уйдёт на прокси с
  подписочным токеном и умрёт.
